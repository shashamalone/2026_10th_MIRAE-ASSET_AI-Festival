# 요청 항목별 NULL 처리 수정 검증

작성일: 2026-09-05. 작업: T-139. 수정 직전 HEAD: `54de40c`.

## 결과

- 기존 56개 + 신규 답변 계약 20개 = 오프라인 회귀 76개 통과.
- 저장된 Q1 1회차 조회 결과 재생: 원래 요청 9항목 모두 값 또는 확인 불가 사유 표시(9/9).
- Q1 SQL은 원래 실행 SQL과 완전히 동일. 매수수익률과 매수가능수량은 NULL 안내로 출력.
- Q1 답변 합성 LLM 호출 0회. 재생 검증에서는 실제 데이터 SELECT 0회이며,
  저장된 원천값과 읽기 전용 서버 카탈로그 메타를 사용했다.
- 실제 모델 전체 파이프라인 재측정, 정답률 재산출, 서버 배포/데이터 적재는 하지 않았다.

## 변경 범위

- `src/agent/prompts.py`: ANSWER_SYSTEM_PROMPT 내부만 변경. 행 부재와 필드 결측을 구별하고,
  계획에만 있는 조건을 실행한 것으로 주장하지 않도록 지시.
- `src/tools/catalog_sql.py`: 확정된 출력 필드→결과 키→근거 컬럼/단위/기준일/0 해석 메타를 반환.
  원래 SQL 투영·필터는 유지. UNION 순위값을 원본 등급으로 표시하지 않도록 구별.
- `src/agent/nodes.py`: 단순 RDB lookup은 코드가 값·결측 사유를 직접 출력.
  혼합/서술 경로는 LLM 설명 뒤에 같은 RDB 블록을 부착. 빈 설명이나 설명 생성 오류가
  확보된 구조화 값을 지우지 못하게 처리.
- `test/catalog-sql/test_answer_contract.py`: NULL, 빈 문자열, 0/false, 미조회, 미해결,
  조회 차단/실패/0건, NaN, 메타상 불가용값, 상품명/큰 수/소수 원문, 기준일,
  서로 다른 행의 값 혼합 방지, 표시 건수, 빈 설명/모델 장애, 조인, 순위값을 검증.

## 제한과 검토 결과

- 요청 보장은 **의도 분석에 남은 요청 항목**부터 적용된다. 원문에서 요구했지만
  intent 단계에서 사라진 항목은 이 수정만으로 복구할 수 없다.
- Q3 만기구분은 컬럼 해소 실패(미조회)이며 NULL로 판정하지 않는다.
  원등급 AA0는 원래 답변에도 있었다. 온톨로지 분류 요청은 intent에서 누락되어
  Graph 계획 자체가 없었다. 이는 별도 의도 분석/조회 계획 개선 과제다.
- `zero_null_rule`의 불가용/사용금지 규칙을 표시하며 원천 0 자체는 보존한다.
  카탈로그 의미의 정확성이나 금융 해석까지 이 테스트가 보증하지는 않는다.
- 기준일 메타는 원천 카탈로그의 연결을 표시한 것이며, 모든 값이 배포일 기준으로
  최신이라는 보증이 아니다. 값이 누락되면 날짜도 확인 불가로 표시한다.
- 최대 20개 표시 행을 기준으로 항목을 출력하고 반환/표시 건수를 명시한다.
- 혼합 경로의 자유 서술 정확성, Graph 근거 확보, 원천 결측 해소는 별도 과제다.
- 기존 자유형 SQL처럼 출력 바인딩이 없는 경로는 컬럼을 추측하지 않고 매핑 미확인으로 표시한다.
