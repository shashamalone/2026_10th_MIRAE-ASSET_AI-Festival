## Q5: 왜 분류근거와 수치 갱신일이 빠졌는가

### 실제 질문 / 이전 답변

> TIGER 미국S&P500의 투자자산군, 투자지역, 운용전략, 복제방식, 총보수와 1·3·6개월 수익률을 알려줘. 분류 근거와 수치 갱신일을 붙여줘.

아래 답변은 5d23ce3 버전의 저장된 **1회차 결과**다. 이번에 Q5 모델을 재실행한 결과가 아니다.

```text

투자지역: 미국
운용전략: 실물복제

3개월 수익률: -5.23%

```

### 발생 단계

1. 분석 intent: `분류 근거`, `수치 갱신일` 모두 fields에 있었다.
2. 검수 intent: 둘 다 유지됐다.
3. RDB 계획: 둘 다 그대로 있었다. Graph/Vector는 계획되지 않았다.
4. 개념/컬럼 확정: 둘을 일반적인 단일 물리 컬럼으로 찾다가 미해결 처리했다.
5. 원천 날짜는 자동 출처 조회 기능 때문에 실제 SQL/결과 행에 있었다.
6. 당시 답변 모델은 미해결 요청과 날짜들을 최종 답변에서 생략했다.

따라서 **Q3처럼 intent에서 잃어버린 사례가 아니다**. Q5의 핵심은 출력용 근거·갱신일을 처리하는 의미 매핑과 답변 연결이다.

실제 assumptions:

```text
요청된 필드 '복제방식'는 대응하는 컬럼을 찾지 못해 결과에서 제외했습니다.
요청된 필드 '분류 근거'는 대응하는 컬럼을 찾지 못해 결과에서 제외했습니다.
요청된 필드 '수치 갱신일'는 대응하는 컬럼을 찾지 못해 결과에서 제외했습니다.
```

### 현재 코드에서 남아 있는 이유

- `분류 근거`는 물리 컬럼 이름이 아니라 “원본 값 → 분류 규칙/정의 → 분류 결과”를 묶어 제공해야 하는 출력이다. 현재 국내ETF에는 이를 구성하는 출력 view가 없다.
- `수치 갱신일`은 `utils.PROVENANCE_CONCEPTS`의 등록 표현이 아니다. `기준일`/`데이터갱신일`/`각수치의기준일`과 같은 처리로 연결되지 않는다.
- `복제방식`도 현재 국내ETF 카탈로그에서 미해결이다. `cu_strtegy=실물복제`를 운용전략 한 항목으로만 보여주고 복제 축으로 분리하지 않는다.
- 이전 NULL/요청 필드 렌더러 수정 후에는 원천 컬럼과 자동 조회된 날짜를 표시할 수 있지만, 그 자체로 분류 규칙을 적용하거나 위 미등록 요청 표현을 의미적으로 해결하지는 않는다.
- Q3에서 추가한 출력 view는 채권용이다. ETF까지 이미 해결됐다고 할 수 없다.

### 총보수 NULL 처리는 해결 — 값이 없는 것은 오류와 다름

이번에 앱이 사용하는 경로를 SELECT로 확인했다:

```json
{
  "pd_itm_no": "KR7360750004",
  "value": null,
  "unit": "percent",
  "as_of": "2026-08-24",
  "source": "PREF01N001",
  "source_column": "cu_charge_rt",
  "method": "raw",
  "is_available": false,
  "unavailable_reason": "NULL",
  "source_priority": 1
}
```

- raw `cu_charge_rt`도 NULL이고, `enriched.product_metric`의 EXPENSE_RATIO도 value=NULL/is_available=false다.
- 현재 행은 PREF01N001 원천, source_priority=1, method=raw다. 따라서 제공 데이터 기준으로 총보수를 확인할 수 없다고 답하면 된다.
- as_of가 존재한다는 사실만으로 NULL 보수 값을 사용할 수는 없다.
- **사용자 확인:** NULL을 사유와 함께 명시하는 것이 이번 해결 기준이다. 이 기준에서는 총보수 NULL 처리는 해결된 것으로 본다. 유효한 값이 없다는 이유만으로 시스템 오류나 미해결 버그로 집계하지 않는다.
- 기대 답변: “총보수: 제공 데이터의 값이 NULL이므로 확인할 수 없습니다.” 임의 0%·외부값으로 채우거나 항목 자체를 생략하면 안 된다.
- 이번에 보수 데이터 적재·교체는 하지 않았다.

## Q5 해결안 (제안; 이번 코드 변경에는 미포함)

1. 갱신일은 일반 SQL 컬럼 검색 대신 출처 요청으로 분류하고, 실제 projection binding의 날짜 근거를 이용해 출력한다. NULL·미조회 날짜는 별도 이유를 표시한다.
2. 분류근거는 채권과 같은 출력 view 방식으로 원본 값·기존 TBox 규칙·분류 결과를 묶는다. 상품명이나 Q5 정답을 하드코딩하지 않는다.
3. ETF 분류축을 분리한다. 기존 `ontology/common.ttl`/`ontology/etf_kr.ttl`에 따라:
   - `wu_inv_ast_type=주식` → `AssetType_Equity`
   - `wu_inv_rgn=미국` → `Region_US`
   - `cu_strtegy=실물복제` → 운용전략 `패시브/Strategy_Passive`, 복제방식 `실물복제/Replication_Physical`
   - 단순 원본값과 정규화된 분류값을 구별하고, 로컬 규칙 적용을 원격 GraphDB 조회라고 쓰지 않는다.
4. 총보수는 현재 NULL 확인 불가 응답을 유지한다. 추가 보강은 선택적인 데이터 확장이며, 이번 Q5 오류 해결의 필수 조건이 아니다.
