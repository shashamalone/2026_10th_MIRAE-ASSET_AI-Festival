> 현대해상화재보험7(후)(콜/후)의 채권 종류, 발행사, 신용등급, 만기구분, 듀레이션을 알려줘. 원본 등급값과 온톨로지 분류값을 함께 제시해줘.

## 원인과 수정

| 누락 지점 | 이전 문제 | 이번 처리 |
| --- | --- | --- |
| 분석·검수 | 뒤 문장의 원본 등급값/온톨로지 분류값이 fields에서 사라짐 | 두 프롬프트에 분리 보존 지시 + 분석/검수 후 명시적 요청 복구 코드 |
| 컬럼 확정 | 만기구분에 대응하는 물리 컬럼이 없어 SELECT에서 제외 | 출력 전용 파생 항목으로 등록; 실제 mat_dt/info_base_dt를 조회 |
| 등급 해석 | crd_grd=AA0 한 값으로 원본과 분류를 구별하지 못함 | 원본 AA0는 그대로, 기존 TBox CreditRating label/altLabel로 AA/Rating_AA 산출 |
| 답변 | 조회되지 않았거나 계획에서 사라진 항목을 답변 모델이 복구하지 못함 | 행별 파생 값/입력 컬럼/규칙/실패 사유를 요청 항목 렌더러에 전달 |

특정 문항 번호·상품명·정답 목록 분기는 없다. 복구 대상 어휘는 기존 도메인 카탈로그와 일반 출력 항목 정의에서 얻는다. 등급/만기 구간 정의는 기존 TTL을 읽으며, AA0→AA나 Q3의 만기값을 코드에 박지 않는다.

만기구분은 원천 상환일자 기준 잔존만기 분류다. 1년=365일, 하한 포함·상한 미포함을 적용했다. 상품명의 콜/후를 해석해서 법적 만기·콜 행사 여부를 확정한 결과는 아니다.
온톨로지 분류는 **로컬 TBox 규칙 적용**이며 **원격 GraphDB에서 해당 상품의 분류 트리플을 조회한 결과가 아니다**.

## 실제 처리 과정

1. 질문 수신 → 분석 LLM → 누락된 두 명시 요청을 코드가 복구.
2. 검수 LLM → 요청 복구 가드를 다시 적용해 삭제되지 않도록 보호.
3. RDB 조회 계획: 요청 7항목 유지. 현재 이 질문은 RDB 1단계만 실행.
4. 카탈로그 컴파일러: 실제 물리 컬럼만 SELECT. 만기구분이라는 가짜 컬럼 생성 없음.
5. 서버에서 1행 반환 → 원본 등급과 날짜에 기존 온톨로지 규칙 적용.
6. 행별 값과 근거를 병합 → 답변 모델 없이 요청 항목별 최종 출력.

### 실제 SQL

```sql
SELECT base.pd_nm AS pd_nm, base.bd_knd AS bd_knd, base.pd_pbcm AS pd_pbcm, base.crd_grd AS crd_grd, base.mat_dt AS mat_dt, base.info_base_dt AS info_base_dt, base.dur AS dur, base.pd_no AS pd_no, base.pd_std_info_update AS pd_std_info_update, base.sale_yield_base_dt AS sale_yield_base_dt
FROM raw.prbd01n001 AS base
WHERE (base.std_pd_mcls_nm::text = E'회사채')
  AND ((((LOWER(REPLACE(base.pd_nm::text, ' ', '')) = E'현대해상화재보험7(후)(콜/후)' OR LOWER(REPLACE(base.pd_abrv_nm::text, ' ', '')) = E'현대해상화재보험7(후)(콜/후)' OR LOWER(REPLACE(base.pd_no::text, ' ', '')) = E'현대해상화재보험7(후)(콜/후)') OR (NOT EXISTS (SELECT 1 FROM raw.prbd01n001 AS identity_probe WHERE LOWER(REPLACE(identity_probe.pd_nm::text, ' ', '')) = E'현대해상화재보험7(후)(콜/후)' OR LOWER(REPLACE(identity_probe.pd_abrv_nm::text, ' ', '')) = E'현대해상화재보험7(후)(콜/후)' OR LOWER(REPLACE(identity_probe.pd_no::text, ' ', '')) = E'현대해상화재보험7(후)(콜/후)') AND POSITION(E'현대해상화재보험7(후)(콜/후)' IN LOWER(REPLACE(base.pd_nm::text, ' ', ''))) > 0))))
```

## 검증 범위와 남은 위험

- 정상 등급뿐 아니라 기존 TBox의 모든 등급 alias, 만기 경계 0/1/3/5/10년, 만기경과, NULL/빈 값/미조회/잘못된 날짜/미상 sentinel을 검사했다.
- 분류가 없거나 중복되거나 TBox가 unavailable이면 추측하지 않고 항목별 확인 불가 사유를 남긴다. 일반 “온톨로지 분류값”에 축이 불명확하면 임의 등급으로 단정하지 않는다.
- 분류 계산에 현재 시각, 듀레이션, 오래된 remaining_days를 대신 사용하지 않는다.
- 요청 복구는 알려진 명사 나열 + 긍정 출력 요청에 한정한 보수적 가드다. 임의 동의어·복합 부정문의 완전한 해석까지 보장하지 않는다.
- 출력 전용 분류 항목의 필터·정렬은 아직 명시적 불가 처리한다. UNION 보조 항목은 기존 4컬럼 계약의 별도 개선이 필요하다.
- **관측된 별도 잔여 문제:** 실제 intent에 원문이 요구하지 않은 subtype=회사채가 남았고 SQL에도 그 조건이 적용되었다. 이 상품은 실제 회사채여서 이번에는 1행이 반환됐지만, 다른 질문의 과잉 필터 위험은 남아 있다. 이번 세 출력 항목 해결이 subtype 추론 전체를 해결한 것은 아니다.
- 기존 retrieved_context의 “기준일 2026-08-24”는 데이터셋 릴리스 날짜 표현이다. 실제 채권 입력 기준일은 답변/원천 행에 표시된 20260821이다. 맥락 요약의 날짜 명칭을 더 명확하게 구분하는 개선 여지가 있다.
- 35문항 전체 회귀/배포 검증은 하지 않았다. T-139 전체 acceptance 완료를 뜻하지 않는 부분 handoff다.
