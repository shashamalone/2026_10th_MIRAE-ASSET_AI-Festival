# 금융 온톨로지 Agent 실험 문서 표준

실험마다 설계서/결과서 형식이 흔들리는 것을 막는다. 산출물은 두 종류뿐이다.

- `{N}_expt_{slug}.md` — 실험 **전**에 쓰는 설계서
- `{N}_result_{slug}.md` — 실험 **후**에 쓰는 결과서

`{N}`은 실험 일련번호, `{slug}`은 소문자 스네이크(예: `pgvector_test`). 번호는 사용자가 주지 않으면 물어본다.

## 절대 규칙

1. 두 문서 모두 **1번 섹션이 초요약본(Digest)** 이다. 예외 없다. 나머지 섹션은 Digest의 각 항목을 상세화한 것이어야 하며, Digest에 없는 결론이 본문에서 새로 등장하면 안 된다.
2. Digest는 아래 고정 6블록을 **이 순서, 이 이름 그대로** 쓴다. 해당 없으면 `해당 없음`이라고 적고 블록을 지우지 않는다.
   - 실험 목적 / 문제정의
   - 실험 환경
   - 실험 설계
   - 실험 결과
   - 실험 결론
   - 후속 조치
3. Digest는 **측정치를 포함한 문장**으로 쓴다. "잘 동작했다"가 아니라 "한국어 질의 6건 중 FTS 3건 적중, 벡터 6건 모두 1위". 수치 없는 결론 문장은 금지.
4. 결과서의 결론은 **판정(PASS / FAIL / PARTIAL / BLOCKED)** 을 반드시 명시하고, 그 판정이 **무엇을 의미하지 않는지**를 한 문장 덧붙인다. (예: "PASS는 '이전 가능'이지 '한국어 FTS가 쓸 만하다'가 아니다.")
5. 추측과 실측을 섞지 않는다. 실측하지 않은 것은 `미측정`으로 표기한다. 실행하지 못한 항목은 결과서 §실행 제약에 이유와 함께 남긴다.
6. 표는 항상 헤더 + 단위 + 판정 열을 갖는다. 숫자는 유효자리를 통일한다.
7. 문서는 한국어 평서체(~다). 이모지 없음. 헤딩 강조 금지, `1. 2.` 번호 체계로 정리한다.

## 작성 절차

1. 사용자가 준 로그·측정치·코드에서 사실만 추출한다. 부족하면 **먼저 질문**한다(필수 확인: 실험 번호, 측정일, 모델/버전, 데이터 규모, 성공 기준).
2. 결과서라면 Digest를 **가장 먼저** 채우고, 그다음 상세 섹션을 Digest 문장에 하나씩 매핑하며 확장한다. 역순으로 쓰지 않는다.
3. `references/expt_template.md` 또는 `references/result_template.md`를 그대로 복사해 채운다. 섹션을 임의로 추가·삭제하지 않는다.
4. 마지막에 `references/checklist.md`로 자가 점검하고, 미충족 항목을 문서 하단이 아니라 사용자에게 보고한다.

## 실험 간 일관성

- 동일 지표는 실험이 바뀌어도 **같은 이름·같은 단위**로 쓴다(예: `Top-1 정확도`, `R@5`, `Top-5 comment coverage`). 새 지표를 도입하면 결과서 §지표 정의에 정의를 남긴다.
- 이전 실험과 비교할 때는 반드시 **무엇이 고정이고 무엇이 변수인지** 표로 먼저 명시한다(코퍼스 동일/측정기 변경 등). 변수 2개를 동시에 바꾼 비교는 결론으로 쓰지 않는다.
- 설계서에는 미리 **성공/실패 기준**을 숫자로 적는다. 결과서는 그 기준을 그대로 인용해 판정한다. 사후에 기준을 바꾸지 않는다.
