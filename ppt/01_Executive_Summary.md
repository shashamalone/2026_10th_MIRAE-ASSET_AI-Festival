# 1. Executive Summary

**{{프로젝트명}}은 금융상품 질문을 수치·관계·서술 근거로 나누어 검색하는 금융 온톨로지 기반 질의응답 Agent다.** 규칙 기반 실행 계획과 엔진별 검증을 구현했으며, 검색된 근거(Evidence)에 기반한 답변과 데이터 부재 시 답변 거절을 지원한다. 다만 **개선 후 전체 정확도와 종단 간 응답시간(E2E) 15초 목표는 아직 검증되지 않았다.**

### 해결하려는 금융 실무 문제

- **수치 오류:** ETF·ETN 혼입, 미계산 괴리율, 신용등급 결측의 의미 차이는 단순 필터만으로도 오답을 만들 수 있다.
- **관계 오해:** 상품의 운용사·발행사·편입기업을 혼동하거나, 문서 미확보를 실제 관계 부재로 해석하면 잘못된 상품 탐색으로 이어진다.
- **근거 시점 혼동:** 사용 가능한 데이터의 상한인 **2026-08-24**와 수치의 실제 기준일을 구분해야 한다. 도메인 기본 기준일은 `business_rules.json`의 **2026-08-21**이며, 행별 기준일이 있으면 이를 우선한다.

### 차별화와 현재 구현 수준

| 비교 항목 | Baseline의 한계 | 본 시스템의 대응 및 상태 |
|---|---|---|
| 순수 대규모 언어모델(LLM) | 정형 수치·관계의 검증 근거와 기준일을 강제하기 어렵다. | **구현 완료:** 결정적 RDB 컴파일러로 지원 조건·정렬을 처리한다. **부분 구현:** 모든 RDB 주장에 대한 표준 근거 계약은 미통합이다. |
| 일반 문서 검색 증강 생성(RAG) | 청크 검색만으로 수치 정렬, 다중 홉 관계, 도메인 위반을 검증하기 어렵다. | **구현 완료:** 온톨로지 검증 Graph와 상품 범위 제한 Vector 검색을 사용하며, 문서 미확보와 검색 결과 없음을 구분한다. |
| 자유형 Text2SQL·Planner LLM | 엔진·의존성·스키마를 잘못 생성할 수 있다. | **구현 완료:** Python 규칙과 의존관계 스케줄러가 실행 계획을 구성한다. 관계 출발점이 모호한 예외에만 제한적 LLM 폴백을 사용한다. |
| 최종 답변 통제 | 검색 결과가 있어도 근거 밖의 설명이 섞일 수 있다. | **부분 구현:** HyperCLOVA X HCX-007이 검색 근거로 답변한다. 일반 답변불가는 지원하지만, 거절 사유 타입 통합과 생성 오류 개선은 남아 있다. |

### 제출 판단과 적용 방향

- **구현 완료:** PostgreSQL·pyoxigraph·pgvector 기반 검색, Intent 분석·재검수, 결정적 보정, 읽기 전용 SQL·SPARQL, Graph 근거 누락 시 결과 폐기.
- **부분 구현:** 상품명 해소 실패 시 부분일치 폴백, 답변 필드 누락·빈 응답, 거절 사유 표준화. 전역 Route Guard와 요청 전체 deadline은 현재 없다.
- **우선 과제:** 생성 오류와 정답 회귀를 보정하고 **35문항 × warm 3회** 전체 평가를 수행한다. 현업 적용은 근거를 추적할 수 있는 상품 탐색 지원을 지향하며, 확장 시 상품군별 카탈로그·온톨로지·근거 확보 상태를 검증한다.
