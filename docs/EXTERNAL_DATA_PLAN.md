# 외부데이터 수집 계획

> **개정 이력**
> - 2026-08-13: 예상 평가 질문 **35문항** 기준으로 우선순위 전면 재조정(`QUERY_COVERAGE_35.md`). 기존 8문항 기준 P0~P3(11건)을 blocking 문항 수 기준으로 교체. 공통 규칙(2절)은 변경 없음.
> - 2026-08-16: **P0 3건 확보 반영** — 국내 ETF 편입종목(부분)·기업 식별자 마스터·기업 지배구조. 우선순위 표에 `상태` 컬럼 추가, 4·5절을 수집 결과와 잔여 작업으로 갱신. 우선순위 자체는 변경 없음(배점 재계산 불필요).

## 1. 목적

35문항 커버리지 측정 결과(`QUERY_COVERAGE_35.md`), **가능 14 / 부분 13 / 불가 8**이다. 특히 **상 난이도 10문항 중 '가능'이 0건**이며, 불가 8문항 중 7문항이 관계·시그널 검색 유형에 몰려 있다.

원인은 세 축으로 수렴한다. ① ETF·펀드 **편입종목(holdings)이 전 도메인 0건** ② 근거 계약이 요구하는 **문서명·발행일·인용문을 낼 문서가 0건** ③ 기업 노드가 채권 발행사에만 존재해 **상품→기업 연결이 성립하지 않음**.

온톨로지가 커버하는 질의 범위를 넓히려면 구성종목·지배구조·서술형 공시 등 주최측 스냅샷에 없는 축을 외부데이터로 보강해야 한다.

**진행 상태 (2026-08-16)** — 위 세 축 중 ①③이 해소됐다. 편입종목 47,016행(ETF 711종), 기업 노드 118,709건, 자회사 29,524행을 확보했다. 남은 병목은 ②**근거 문서 0건**이며, 이것이 단일 항목으로 8문항을 막는 최대 blocking으로 남았다.

주의: 위 `가능 14 / 부분 13 / 불가 8`은 **08-13 측정치로, 편입종목·지배구조 확보 이전 기준**이다. 확보분을 반영한 재측정이 아직 수행되지 않았다(5절 잔여 작업 1번).



## 2. 공통 규칙

- **시점 기준**: 주최측 2026-07-11 스냅샷이 절대 기준이다. 외부데이터는 **반드시 2026-07-11 이전 시점(as_of ≤ 2026-07-11)** 데이터만 허용한다. 이후 시점 데이터가 섞이면 미래 정보 유출(look-ahead)로 간주해 폐기한다.
- **취득 형태**: 실시간 API 연동이나 상시 크롤링 파이프라인은 구축하지 않는다. **1회 정적 스냅샷 취득**만 수행하고, 취득 시점의 파일을 그대로 고정해 재현 가능하게 보관한다.
- **우선순위**: 외부데이터가 주최측 데이터와 상충하면 **주최측 데이터를 우선**한다. 상충이 발견된 경우 폐기하지 말고 답변 evidence에 "외부 소스 X와 상충, 주최측 값 채택"과 같이 상충 사실 자체를 기록한다.
- **메타데이터**: 수집 파일마다 사이드카 JSON을 함께 둔다. 스키마는 `{source, as_of, retrieved_at, url}` 고정. 사이드카 파일명은 **확장자를 바꾸지 않고 원본 파일명 전체에 `.meta.json`을 덧붙인다**(`a.xls` → `a.xls.meta.json`, `a.json` → `a.json.meta.json`). 확장자 치환 방식은 원본이 `.json`일 때 이름이 충돌하므로 쓰지 않는다. URL에 인증키가 포함되면 키 부분을 마스킹해 기록한다.
  - `source`: 발행 기관/사이트명
  - `as_of`: 데이터 기준 시점 (반드시 2026-07-11 이전)
  - `retrieved_at`: 실제 다운로드/취득 일시
  - `url`: 원본 출처 URL
- **저장 위치**: `data/external/{항목}/` 하위에 항목별로 분리 저장. 파일명은 `{식별자}_{as_of}.{확장자}` 형식의 **ASCII만** 사용해 시점을 파일명만으로 식별 가능하게 한다 (예: `data/external/etf_kr_holdings/kodex_200_20260710.xls` + `kodex_200_20260710.xls.meta.json`). 한글 파일명은 NFD 정규화 문제로 경로 참조가 깨진 전례가 있어 금지한다.
- **검증 스크립트**: 수집 완료 후 `as_of > 2026-07-11`인 파일이 섞였는지 사이드카 JSON을 스캔해 걸러내는 검증 스크립트를 1개 둔다 (`EDA/validate_external.py` — 모든 사이드카의 `as_of`를 파싱해 기준일 초과 건을 리스트업하고 실패 시 종료 코드 1을 반환). **구현 완료** — 사이드카 필수 키 누락·원본 없음·기준일 초과·URL 인증키 노출을 검사한다. 현재 원천 3,474건 전량 통과. (`EDA/src/`는 jupytext 노트북 소스 전용이므로 실행 스크립트는 `EDA/` 직하에 둔다 — DATA_LAYER_PLAN 참조)
- **처리 결과 위치**: `data/external/`은 원천 보관소이며 질의에 직접 쓰지 않는다. 반드시 `EDA/build_*.py`로 정규화해 `data/relations/`(관계) 또는 `data/enriched/`(스칼라)로 떨어뜨린 뒤 사용하고, 사이드카의 `as_of`·`source`를 결과 테이블 컬럼으로 승계한다. 계층 정의와 파일명 규칙은 **DATA_LAYER_PLAN.md**가 단일 기준이다.

## 4. 항목별 상세 (P0)

35문항 재조정으로 P0가 3건 → 6건이 됐다. 아래 상세는 기존 3건분이다. 신규 P0 3건(근거문서·기업 식별자 마스터·공모펀드 편입내역)은 취득 경로가 각각 4.1(운용사 공시자료실)·4.3(DART)과 같은 소스를 공유하므로, 착수 순서(5절)에 따라 해당 절차에 묶어 처리한다.

각 항목의 '예상 난관'은 착수 전 기록이다. **실제로 무엇이 맞고 틀렸는지는 각 절의 '수집 결과'**에 남긴다 — 남은 항목의 난이도 예측을 보정하기 위한 기록이다.

### 4.1 국내 ETF 구성종목(PDF/포트폴리오)

- **취득 절차**: 
  - ① KRX 정보데이터시스템에서 ETF 상품별 PDF(구성종목 내역) 조회
  - ② 실패 시 운용사 홈페이지 공시자료실(예: 삼성자산운용 KODEX, 미래에셋 TIGER)에서 일별 PDF 다운로드 
  - ③ 2026-07-11 기준일에 가장 가까운(그 이전) 공시일 파일 선택 
  - ④ `pd_itm_no`/`pd_itm_no_ma`로 국내 ETF 마스터와 매핑 
  - ⑤ PDF 표를 파싱해 (ETF코드, 구성종목명, 종목코드, 비중) 행 단위 CSV로 정규화.
- **예상 난관**: 
  - PDF 표 레이아웃이 운용사마다 달라 파싱 규칙을 개별화해야 한다.

### 5.2 잔여 작업 — 수집보다 적재가 먼저다

**이미 받아둔 관계 데이터 76,540행(편입종목 47,016 + 자회사 29,524)이 질의에 연결되지 않은 채로 있다.** 이 상태에서 신규 수집을 더 해도 점수로 환산되지 않으므로, 1~3번을 4번보다 먼저 처리한다.
