# Q22 복합 테마 의도 복구 검토

## 결론

Q22 실패의 직접 원인은 Graph 데이터 부재나 `캠브리콘` 별칭 실패가 아니다. Claude tester의 정상 환경 N=1 실행에서 캠브리콘 편입 후보 14건은 확보됐지만, 의도 분석기가 질문의 `중국 반도체 ETF`를 Graph 테마 관계로 만들지 않고 국내ETF 하위유형 `반도체`로 남겼다. `반도체`는 검증된 RDB 상품유형이 아니므로 Graph 성공 뒤 RDB 단계가 중단됐다.

## 변경

- 편입·보유 관계가 있고 국내ETF를 대상으로 하며, 원문에 `<지역/설명어> <하위유형> ETF`가 연속해서 명시된 경우에만 그 전체 표현을 `tagged_with` Graph 관계로 복원한다.
- 복원한 테마에 포함되는 잘못된 하위유형은 기존 중복 제거 규칙으로 RDB 필터에서 제거한다.
- `ETF명`·`ETN명`은 사용자 표현 별칭이므로 카탈로그의 `상품명` 개념으로 정규화한다.
- 해외 거래소 상장 범위가 명시됐거나, 원문에 복합 표현이 없거나, 편입 관계가 없으면 이 규칙을 적용하지 않는다.
- 상품 목록·상품코드·편입비중 등 정답값은 하드코딩하지 않는다. 실제 후보와 교집합은 Graph resolver가 검증한다.

## 실제 Q22 흐름

질문:

`캠브리콘이 실제 편입된 중국 반도체 ETF를 찾아줘.`

Claude tester가 생성한 원래 의도:

- 도메인: 국내ETF
- 하위유형: 반도체
- 관계: 국내ETF가 캠브리콘을 편입
- 출력: ETF명, 티커, 편입비중, 편입기준일

guard 적용 뒤:

- 하위유형: 없음
- 관계 1: 국내ETF가 캠브리콘을 편입
- 관계 2: 국내ETF가 `중국 반도체` 테마와 연결
- 출력: 상품명, 티커, 편입비중, 편입기준일
- RDB 의존성: 두 Graph 결과의 교집합

2026-09-06 원격 Graph를 읽기 전용으로 조회하고 같은 의도를 LLM 호출 없이 Graph→교집합→RDB→답변 경로로 재생한 결과는 다음과 같다.

- 캠브리콘 편입 후보: 14건
- 중국·반도체 테마 후보: 5건
- 교집합: 3건
  - `KR7396520009` TIGER 차이나반도체FACTSET, 9.86%
  - `KR70162L0003` KODEX 차이나AI반도체TOP10, 10.45%
  - `KR70164G0008` RISE 차이나AI반도체TOP4Plus, 14.90%

## 검증

- `py -3.13 -m pytest test/catalog-sql/test_semantic_plans.py -q`: 48 passed.
- 실제 tester 의도에 guard를 적용한 원격 Graph→RDB 무과금 재생: RDB 3건, 위 세 상품코드와 편입비중 확인.
- 답변 표면 검사: 교집합 밖 Graph 후보, 내부 단계 ID, 물리 컬럼 미노출.

## 남은 별도 과제

- 국내ETF `티커`는 ISIN인 `상품코드`와 다른 값이다. 이를 상품코드로 임의 치환하지 않고, `enriched.etf_kr.ticker`를 정식 카탈로그 필드로 연결해야 한다.
- `편입기준일`이 출력 별칭만 있는 Graph plan에서 빈 객체로 렌더링되는 문제는 `evidence_contract.py`의 Graph 필드 추출을 별도 수정해야 한다.
- 원격 Graph는 아직 2026-07-10 편입 스냅샷이다. 2026-08-21 후보 번들은 별도 T-146에서 생성·검증했지만 tester의 우선순위 지시에 따라 원격 적재는 보류했다.
