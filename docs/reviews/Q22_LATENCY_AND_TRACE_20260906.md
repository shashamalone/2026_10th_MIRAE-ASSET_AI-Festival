# Q22 지연·실행 추적 보완 기록 (2026-09-06)

## 결론

Q22의 정답 데이터와 관계 조회는 정상이다. 1회 유료 E2E에서 중국 반도체 ETF 3개, 편입비중, 티커, ISIN, 편입기준일을 정확히 반환했다. 남은 문제는 정답률이 아니라 불필요한 LLM 컬럼 추론으로 인한 지연과 공개 `think_trace`의 내부 단계명 노출이었다.

## 확인한 1회 실행

- 기준 커밋: `9f7c967`
- 총 소요: 62,233.5ms
- 의도 분석: 4,164.9ms
- 의도 검증: 6,386.8ms
- Graph 조회: 1,394.2ms
- RDB 단계: 50,268.9ms
- SQL 실행: 44.7ms
- 마지막 개념 추론 호출: 1,258.4ms (`편입내역 문서명`, `근거 문장`)
- 결과: 상품 3개와 편입비중 10.45%, 14.9%, 9.86%, 티커 `0162L0`, `0164G0`, `396520`, 편입기준일 `2026-07-10` 확인

RDB 단계의 약 50초는 DB나 SQL이 느린 것이 아니다. 문서 출처 필드를 RDB 컬럼으로 해석하려다 네트워크 LLM 호출과 재시도 대기를 거친 것이 원인이다. 따라서 Graph 재적재는 이 지연의 해결책이 아니다.

## 변경

1. `편입내역 문서명`, `근거 문장`, `인용문` 등 문서 증거 필드는 RDB 컬럼 후보에서 제외한다.
2. 문서 증거 필드는 `build_resolved_schema`에서도 건너뛰고 문서 근거 계층에서 확인한다는 기록을 남긴다.
3. 공개 `think_trace`는 `graph_R1`, `graph_RT1`, `rdb_국내ETF` 대신 `관계 조회 1`, `관계 조회 2`, `국내ETF 데이터 조회`로 표시한다.
4. 내부 단계명을 포함한 차단 사유는 공개 요약에서 `선행 조회`로 치환한다.

이 변경은 상품명·티커·편입비중·편입기준일 값의 수집 경로를 바꾸지 않는다. 문서명과 인용 근거만 RDB가 아닌 provenance/vector 계층이 담당한다.

## 회귀 방지

- 문서 증거 필드가 `collect_needed_concepts`에 포함되지 않는지 검증한다.
- 미지 개념 LLM 폴백을 예외로 막은 상태에서도 Q22의 RDB 개념이 전부 결정론적으로 해석되는지 검증한다.
- 공개 실행 요약에 내부 단계 ID가 나타나지 않는지 검증한다.

Claude tester의 중복 유료 실행 금지 지시에 따라 이 수정 뒤 Q22 유료 E2E를 추가 실행하지 않는다. 최종 배포 후에는 사용자가 승인한 단건 smoke에서 응답시간과 공개 출력만 확인한다.

## Graph 재적재와의 관계

원격 Graph는 현재 2026-07-10 편입 스냅샷이고, T-146의 2026-08-21 후보 번들은 별도로 준비돼 있다. tester가 제출 전 재적재를 중지하라고 명령했으므로 이 변경에서는 원격 Graph를 수정하지 않았다. 재적재 여부와 실제 cutover 결과는 통합·배포 기록에 별도 기입해야 한다.
