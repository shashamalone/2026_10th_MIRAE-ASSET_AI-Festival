## 이번 변경

`src/agent/nodes.py`의 출력 경계를 다음처럼 정리했다.

1. `no_rows`는 “조회 결과가 없어 확인할 수 없습니다.”로 표시한다.
2. `query_failed`와 `blocked`는 “제공 데이터로 확인할 수 없습니다.”로 표시한다.
3. 동일한 확인 불가 사유의 필드는 한 줄에 묶어 사유를 한 번만 표시한다.
4. `answer`에서 `rdb_채권`, `graph_R1` 같은 실행 단계 ID와 `raw.*` 물리 컬럼, Graph 실행 경로를 제거한다.
5. RDB 근거는 `retrieved_context`에 공식 데이터셋명·기준일·건수·근거 컬럼으로 남긴다. SQL 전문은 노출하지 않는다.
6. Graph 결과의 키는 상품명·상품코드·편입비중·편입 기준일·출처처럼 사용자용 이름으로 표시한다.
7. 원시 실행 상태와 단계 ID는 디버깅용 `think_trace`에 유지한다.
8. RDB 필터로 소비되는 Graph 후보 집합은 최종 답변에서 다시 나열하지 않는다. Q22의 캠브리콘 후보 14개와 테마 후보 5개는 중간 근거이고, 답변에는 교집합 3개만 표시한다.
9. Graph의 편입비중 구조체는 JSON 진단값 대신 `10.45%` 같은 사용자용 수치로 표시한다.

## Q22 실측

Q22의 한글 `캠브리콘` 표기 해소는 선행 커밋 `495a350`에 이미 구현되어 있다. 실행 시 LLM 번역이나 유사도 추측을 사용하지 않고, 적재 원천에서 검토한 Cambricon ticker·ISIN만 조회한다.

2026-09-06에 원격 Oxigraph endpoint를 읽기 전용으로 직접 조회했다. 유료 LLM 호출은 없었다.

- 캠브리콘 편입 조회: 성공, ETF 14개.
- 중국·반도체 테마 교집합: ETF 5개.
- 최종 교집합: 3개.
  - `KR7396520009` TIGER 차이나반도체FACTSET: 9.86%, 2026-07-10, TIGER.
  - `KR70162L0003` KODEX 차이나AI반도체TOP10: 10.45%, 2026-07-10, KODEX.
  - `KR70164G0008` RISE 차이나AI반도체TOP4Plus: 14.90%, 2026-07-10, RISE.

따라서 Q22의 엔티티 해소 실패 원인은 데이터 부재가 아니라 배포본에 `495a350` 이후 코드가 포함되지 않은 것이다. 현재 Graph 데이터 재적재는 엔티티 해소 복구의 선행조건이 아니다.

의도를 검토된 형태(캠브리콘 편입 관계 + 중국·반도체 테마 관계)로 고정하고 동일한 원격 Graph와 RDB API를 사용한 Graph→교집합→RDB→답변 생성 전체 경로에서도 RDB 결과 3건을 확인했다. 세 상품코드와 9.86%·10.45%·14.90%가 답변에 포함됐고, 교집합 밖 상품과 내부 단계 ID·컬럼명·Graph 실행 경로는 답변에 포함되지 않았다.

Claude tester의 공식 Q22 N=1에서는 별칭 조회가 성공해 캠브리콘 편입 ETF 14개를 확보했지만, LLM이 질문의 “중국 반도체 ETF”를 Graph 테마 관계로 만들지 않고 RDB 하위유형 `반도체`로 남겼다. 이 값은 검증된 하위유형이 아니어서 RDB 단계가 중단됐다. 따라서 Q22 완전 복구에는 데이터 재적재가 아니라, 명시된 복합 테마를 Graph 관계로 복원하는 intent guard 후속 수정이 필요하다.
