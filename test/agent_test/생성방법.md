
# 핸즈온 실행 가이드

아래 절차는 처음부터 노트북을 만들고, 실행하고, 코드를 수정한 뒤 원래 Python 파일에 반영하는 전체 흐름이다.

## 1. 작업 폴더 준비

PowerShell을 열고 저장소 루트로 이동한다.

    cd "C:\Users\rladl\Desktop\2026_MIRAE_ASSET_AI-Festival\2026_10th_MIRAE-ASSET_AI-Festival"

현재 위치가 맞는지 확인한다.

    Get-Location
    Test-Path .\src
    Test-Path .\test\notebook\build_notebook.py

두 번째와 세 번째 명령 결과가 모두 True여야 한다. False가 나오면 저장소 루트가 아닌 곳에서 실행 중인 것이다.

Jupyter가 설치되어 있는지도 확인한다.

    python --version
    jupyter --version

프로젝트 가상환경을 사용한다면 Jupyter 실행 전에 먼저 활성화한다.

    .\.venv\Scripts\Activate.ps1

가상환경 이름은 프로젝트 설정에 따라 다를 수 있다.

## 2. 노트북 생성 또는 갱신

src의 최신 Python 파일을 바탕으로 통합 노트북을 만든다.

    python test/notebook/build_notebook.py

정상 실행 시 다음과 비슷한 메시지가 나온다.

    wrote ...\test\notebook\src_all_in_one.ipynb (49 cells)

이 명령은 test/notebook/src_all_in_one.ipynb를 새로 작성한다. 즉, 노트북 안에서 아직 Python 파일로 반영하지 않은 수정은 사라질 수 있다.

따라서 다음 상황에서는 순서를 지킨다.

- src를 직접 수정했다면: build_notebook.py를 실행해 노트북을 갱신한다.
- 노트북을 수정했다면: 먼저 sync_to_py(dry_run=False)를 실행해 src에 반영한 뒤 노트북을 다시 생성한다.
- 어느 쪽을 기준으로 해야 할지 모르겠다면: 노트북을 재생성하기 전에 git diff와 dry run 결과를 먼저 확인한다.

## 3. Jupyter로 열기

저장소 루트에서 다음 중 하나를 실행한다.

    jupyter notebook test/notebook/src_all_in_one.ipynb

또는

    jupyter lab test/notebook/src_all_in_one.ipynb

브라우저가 열리면 src 통합 노트북을 선택한다.

## 4. 첫 실행

노트북은 위에서 아래 순서로 실행한다.

1. setup 셀을 실행한다.
2. config부터 kb.build_bond_index까지 모듈 셀을 순서대로 실행한다.
3. 각 모듈 셀 아래에 registered: 모듈명 메시지가 나오는지 확인한다.
4. 노드별 테스트 영역으로 내려간다.

setup 셀을 실행하지 않고 모듈 셀부터 실행하면 %%module을 알 수 없다는 오류가 난다. 커널을 재시작한 경우에도 setup 셀부터 다시 실행해야 한다.

모든 셀을 한 번에 실행하려면 Jupyter 메뉴에서 Kernel > Restart Kernel and Run All Cells를 사용할 수 있다. DB나 API 키가 없는 환경에서는 E2E 셀에서 오류가 날 수 있으므로, 그런 경우에는 모듈 셀과 노드별 테스트까지만 확인한다.

## 5. 테스트 질문 바꾸기

노드별 테스트 영역의 TEST_QUESTION 값을 실제 질문으로 바꾼다.

    TEST_QUESTION = "VOO의 정식 상품명과 총보수를 알려줘"

가능하면 expected_qa 폴더의 예상 평가 질문을 사용한다. 질문 셀을 수정한 뒤 해당 셀부터 다시 실행한다.

그 다음 초기 state 셀을 실행한다. 이후 각 테스트 셀은 이전 셀의 state를 이어받으므로 중간 셀을 건너뛰지 않는다.

## 6. 노드별 실행 결과 확인

다음 순서로 셀을 실행한다.

    N.extract_query_frame(state)
    N.ground_query(state)
    N.validate_query(state)
    N.select_route(state)
    N.execute_rdb(state)
    N.verify_results(state)
    N.render_answer(state)

각 셀은 보통 다음 형태로 state를 누적한다.

    out = N.extract_query_frame(state)
    state.update(out)
    out

각 단계에서 다음을 확인한다.

- extract_query_frame: 질문의 의도와 상품명, 조건이 올바르게 추출되었는가
- ground_query: 질문 조건이 스키마와 데이터 기준에 맞게 구체화되었는가
- validate_query: 허용되지 않는 값이나 답변 불가 사유가 탐지되었는가
- select_route: 어떤 조회 경로를 사용할지 올바르게 결정되었는가
- execute_rdb: 조회 결과가 나왔는가
- verify_results: 결과와 근거가 검증되었는가
- render_answer: 근거와 기준일이 포함된 답변이 만들어졌는가

각 노드 뒤에 state를 직접 확인할 수도 있다.

    state["intent"]
    state["plan"]
    state["route"]
    state["results"]
    state["evidence"]
    state["abstain"]
    state["trace"]

validate_query 결과에 state["abstain"] 값이 있으면 답변 불가 경로다. 이 경우 조회 결과가 없다는 뜻과 혼동하지 말고 abstain의 사유를 확인한다. 이후에는 render_answer를 실행해 보류 답변이 올바르게 생성되는지 확인한다.

## 7. E2E 실행

노드별 실행이 끝난 뒤 전체 그래프를 실행한다.

    from agent.agent_core import ask
    resp = ask(TEST_QUESTION)
    resp

E2E 실행에는 DB 연결 정보와 HyperCLOVA X API 키가 필요할 수 있다. 이 값이 없는 환경에서는 E2E 실패만으로 코드 로직이 잘못되었다고 판단하지 않는다.

노드별 테스트와 E2E 결과가 다르면 다음을 먼저 확인한다.

- E2E 전에 최신 모듈 셀을 모두 재실행했는가
- 테스트 질문 셀과 초기 state 셀을 다시 실행했는가
- DB 접속 환경이 같은가
- E2E 응답의 abstain과 evidence를 확인했는가

## 8. 노트북에서 코드 수정하기

예를 들어 agent/nodes.py를 수정하려면 해당 모듈 셀을 찾는다. 셀 첫 줄은 다음과 같다.

    %%module agent.nodes agent/nodes.py

셀 본문에서 필요한 부분을 수정하고 셀을 실행한다. 셀을 실행하면 sys.modules 안의 agent.nodes가 새 코드로 교체된다.

단, 이미 agent.nodes를 import한 하위 모듈이나 테스트 셀은 자동으로 갱신되지 않는다. 따라서 수정 범위에 따라 다음 셀을 다시 실행한다.

    수정한 모듈 셀
    -> 해당 모듈을 import하는 하위 모듈 셀
    -> 테스트 질문 셀
    -> 초기 state 셀
    -> 관련 노드 테스트
    -> E2E 셀

가장 확실한 방법은 커널을 재시작한 뒤 setup부터 전체 모듈 셀을 순서대로 다시 실행하는 것이다.

## 9. 수정 내용을 Python 파일로 반영하기

노트북 수정이 끝나면 먼저 Ctrl+S로 저장한다. 저장하지 않은 내용은 sync_to_py가 읽지 못한다.

마지막의 .py 반영 셀에서 먼저 미리보기만 실행한다.

    sync_to_py()

출력은 다음처럼 해석한다.

    same: agent/nodes.py
    CHANGED: agent/nodes.py  (dry_run - 실제 반영 아님)

CHANGED 목록이 의도한 파일만 포함하는지 확인한다. 확인이 끝나면 실제 반영을 실행한다.

    sync_to_py(dry_run=False)

정상 반영 시 다음과 비슷한 결과가 나온다.

    WROTE: agent/nodes.py

반영 뒤 PowerShell에서 변경 내용을 확인한다.

    git diff -- src

diff에 예상하지 않은 파일이나 대량의 변경이 나오면 추가 작업을 멈추고 원인을 확인한다. 노트북을 재생성하기 전에 먼저 dry run과 diff를 확인하는 습관을 권장한다.

## 10. src에서 노트북으로 갱신하기

Python 파일을 편집기에서 직접 수정한 경우에는 저장한 뒤 저장소 루트에서 다음을 실행한다.

    python test/notebook/build_notebook.py

이때 노트북의 모듈 셀은 src의 최신 원문으로 교체된다. 노트북의 테스트 질문과 테스트 셀도 생성 스크립트에 정의된 내용으로 다시 만들어진다.

노트북에서만 수정한 내용이 있다면 이 명령 전에 반드시 다음을 실행한다.

    sync_to_py(dry_run=False)

## 11. 오류가 날 때 초기화 순서

ModuleNotFoundError, 등록되지 않은 모듈, 오래된 결과가 보이면 다음 순서로 초기화한다.

1. Jupyter 메뉴에서 Kernel > Restart Kernel을 실행한다.
2. setup 셀을 실행한다.
3. 모듈 셀을 맨 위부터 의존성 순서대로 다시 실행한다.
4. 테스트 질문 셀과 초기 state 셀을 실행한다.
5. 노드별 테스트를 다시 실행한다.

%%module 셀 내부의 import 문을 임의로 바꾸지 않는다. 이 노트북은 원래 src 파일의 import 문을 그대로 유지하는 것을 전제로 하며, 그래야 sync_to_py 왕복이 원문 기준으로 동작한다.

## 12. 최종 체크리스트

    [ ] 저장소 루트에서 build_notebook.py를 실행했다.
    [ ] setup 셀을 먼저 실행했다.
    [ ] 모듈 셀을 의존성 순서대로 실행했다.
    [ ] 테스트 질문과 초기 state를 실행했다.
    [ ] validate_query의 abstain 여부를 확인했다.
    [ ] evidence와 기준일이 답변에 포함되는지 확인했다.
    [ ] 필요한 경우 E2E를 DB·HyperCLOVA X 환경에서 실행했다.
    [ ] 노트북을 Ctrl+S로 저장했다.
    [ ] sync_to_py() dry run 결과를 확인했다.
    [ ] sync_to_py(dry_run=False)로 의도한 파일만 반영했다.
    [ ] git diff -- src로 최종 변경을 확인했다.

핵심은 src와 노트북을 서로 다른 코드로 오래 유지하지 않는 것이다. src를 기준으로 노트북을 재생성하거나, 노트북 수정분을 sync_to_py로 먼저 src에 반영한 뒤 다시 생성한다.

## Conda 전용 환경으로 설치하기 (권장)

기존 base 환경이나 다른 프로젝트 환경에 설치하지 않고, 이 프로젝트 전용 Conda 환경을 만든다.

Anaconda Prompt 또는 PowerShell에서 실행한다.

    conda create -n mafest-agent python=3.11 -y
    conda activate mafest-agent

Python 버전을 확인한다.

    python --version
    where.exe python

출력 경로에 envs\mafest-agent가 포함되어 있어야 한다.

프로젝트 의존성은 requirements.txt 기준으로 설치한다.

    python -m pip install --upgrade pip
    python -m pip install -r requirements.txt

통합 노트북을 실행하려면 Jupyter 커널도 같은 환경에 설치한다.

    python -m pip install jupyterlab notebook ipykernel
    python -m ipykernel install --user --name mafest-agent --display-name "Python (mafest-agent)"

이제 노트북을 실행한다.

    jupyter lab test/notebook/src_all_in_one.ipynb

브라우저에서 노트북을 열고 Kernel > Change Kernel > Python (mafest-agent)를 선택한다. 커널 이름이 Python (mafest-agent)인지 확인한 뒤 setup 셀을 실행한다.

### 설치가 제대로 되었는지 확인

노트북의 새 셀에서 다음을 실행한다.

    import sys
    print(sys.executable)

출력 경로가 다음과 비슷해야 한다.

    ...\anaconda3\envs\mafest-agent\python.exe

주요 패키지도 확인할 수 있다.

    import pandas
    import langgraph
    import pyoxigraph
    import psycopg
    print("package check: OK")

### Conda 환경을 다시 사용할 때

새 터미널을 열 때마다 다음만 실행하면 된다.

    conda activate mafest-agent

    jupyter lab test/notebook/src_all_in_one.ipynb

### 환경 삭제가 필요한 경우

환경 안의 패키지만 삭제되며 저장소의 소스와 데이터는 삭제되지 않는다.

    conda deactivate
    conda env remove -n mafest-agent

### DB와 API 키

Python 환경을 만들어도 PostgreSQL 서버와 HyperCLOVA X API 키가 자동으로 준비되지는 않는다. E2E 실행 전 .env와 PostgreSQL 접속 상태를 별도로 확인한다.

- .env에는 API 키와 비밀번호를 기록하고 Git에 커밋하지 않는다.
- DB가 없으면 패키지 설치는 성공해도 execute_rdb와 E2E는 실행되지 않는다.
- build_notebook.py로 노트북을 생성하는 작업만 할 때는 DB와 API 키가 없어도 된다.
