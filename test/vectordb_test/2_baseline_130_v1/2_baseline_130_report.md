# 130개 온톨로지 Baseline 검색 품질 검증 보고서

## 1. 테스트 목적

본 테스트는 `artifacts/bond_terms.json`에 실제 적재된 **온톨로지 검색사전 130개**를 기준으로,  
사용자 질의를 온톨로지 용어로 grounding하는 검색 품질을 측정하기 위해 수행했다.

1차 테스트는 10건의 합성 코퍼스를 사용했기 때문에 경쟁 용어가 거의 없었다.  
이번 130 baseline은 실제 온톨로지 용어 전체를 대상으로 다음을 확인하는 것이 목적이다.

- FAISS → pgvector 이전 이후에도 검색 품질이 유지되는지
- Vector Search의 Top-1 / Top-3 성능이 어느 수준인지
- FTS와 Vector를 결합한 Hybrid Search가 실제로 도움이 되는지
- `BOND_SCORE_FLOOR = 0.45`가 관련성 판정 기준으로 사용할 수 있는지
- 유사 금융용어, 동의어, 자연어 질의에서 어떤 종류의 실패가 발생하는지
- 향후 221개 검색사전 확장 전 비교 기준선(baseline)을 확보하는 것

## 2. 테스트 대상

### 2.1 검색 코퍼스

- 실제 온톨로지 검색 용어: **130건**
- 출처: `artifacts/bond_terms.json`
- 임베딩 모델: `bge-m3`
- 임베딩 차원: `1024`
- 거리 함수: cosine similarity
- 기존 임베딩 캐시 재사용: **130건 전부 재사용**
- 문서 임베딩 신규 API 호출: **0회**

현재 `build_bond_index.py`는 `rdfs:comment`가 존재하는 리소스만 인덱싱한다.  
따라서 `rdfs:label`은 있지만 comment가 없는 코드리스트 개체 91건은 아직 검색 대상에 포함되지 않는다.

### 2.2 실제 130건에서 확인된 구조적 특징

130개 검색사전에는 동일한 `rdfs:label`을 공유하는 용어가 존재한다.

예:

- `fp:RiskGrade` / `fp:hasRiskGrade` → 투자위험등급
- `fp:AssetManager` / `fp:managedBy` → 운용사
- `fp:Issuer` / `fp:documentPublisher` → 발행기관

동일 label 그룹은 총 **16쌍, 32개 용어**다.

또한 의미적으로 가까운 용어군이 밀집되어 있다.

| 혼동군 | 용어 수 |
|---|---:|
| 등급 | 14 |
| 수익률 | 12 |
| 발행 | 13 |
| 수치 | 5 |
| 만기 | 4 |

따라서 단순 Top-1만으로 grounding 품질을 판단하면 클래스/프로퍼티 또는 유사 개념 간 경쟁을 과도하게 실패로 계산할 수 있다.

## 4. 평가 지표

### 4.1 Top-1 Strict

정답 URI 하나만 정확히 1위로 반환해야 성공으로 인정한다.

예:

```text
질의: "운용사가 어디야?"
정답: fp:managedBy
```

`fp:AssetManager`가 1위라면 strict 기준에서는 실패다.

### 4.2 Top-1 Lenient

클래스와 프로퍼티가 동일 label을 공유하고 의미적으로 둘 다 타당한 경우, 사전에 정의한 허용 URI 집합 안에 들어오면 성공으로 인정한다.

예:

```text
fp:AssetManager
fp:managedBy
```

둘 중 하나가 1위면 성공으로 인정할 수 있다.

### 4.3 Recall@3

정답 또는 허용 가능한 정답이 Vector Search 상위 3개 안에 포함되는지 측정한다.

본 지표는 다음 단계 grounding에 후보를 몇 개 전달해야 하는지 판단하기 위한 핵심 지표다.

### 4.4 FTS Hit

PostgreSQL Full Text Search가 기대 용어를 검색 결과에 포함하는지 측정한다.

### 4.5 Hybrid Top-1

Vector Search와 FTS 결과를 RRF(Reciprocal Rank Fusion)로 결합했을 때 최종 1위가 정답인지 측정한다.

### 4.6 Noise False Positive

금융 온톨로지와 무관한 질문에서 검색 점수 `0.45` 이상인 후보가 발생하는 비율을 측정한다.

## 6. 주요 발견

### 6.1 Top-1보다 Top-3 전달이 적절하다

1위와 2위 검색 점수 차이:

```text
중앙값  0.0318
최소값  0.0001
0.02 미만  18/60 = 30%
```

즉 답변 가능 질의 3건 중 약 1건은 1위와 2위가 거의 동점이다.

검색 성능은:

```text
Top-1 Strict  75.0%
Recall@3      96.7%
```

이므로 2단계 grounding에 Top-1 하나만 전달하면 검색 단계에서 약 25%를 잃지만,  
Top-3 후보를 전달하면 손실을 약 3.3%까지 낮출 수 있다.

### 결론

```text
Vector Search
     ↓
Top-3 후보
     ↓
Grounding / Validation
```

구조를 기본으로 사용한다.

---

### 6.2 Hybrid Search(RRF)는 기본 경로로 사용하지 않는다

130건 기준:

```text
Vector 단독 Top-1       51/60
Hybrid RRF Top-1        50/60
```

Hybrid Search가 Vector 단독보다 1건 낮았다.

정확 용어 질의도:

```text
Vector   12/12
Hybrid   11/12
```

로 감소했다.

원인은 FTS가 반드시 정답을 반환하지 않으며, 잘못된 FTS ranking이 RRF를 통해 Vector Search의 올바른 순위를 밀어낼 수 있기 때문이다.

### 결론

- Vector Search를 기본 검색 경로로 사용한다.
- RRF는 기본 경로에서 제외한다.
- FTS를 사용하더라도 Vector ranking을 덮지 않는 보조 수단으로 제한한다.

---

### 6.3 실제 평가 질문 원문을 FTS에 직접 넣으면 안 된다

실제 평가 35문항을 PostgreSQL FTS로 측정한 결과:

```text
plainto_tsquery (AND)   0/35
to_tsquery (OR)        33/35
```

AND 방식은 `알려줘`, `제시해줘` 등 문서에 없는 토큰 하나 때문에 전체 질의가 0건이 되는 문제가 있다.

반대로 OR 방식은 검색 결과는 많이 회수하지만 정밀도가 크게 떨어졌다.

예:

```text
기대:
발행사 / 신용등급 / 표면금리 / 만기일

OR 결과 상위:
신용등급 보유 / 신용등급 상태 / 지분율 / 편입비중 / 총보수요율
```

또한 원문에 괄호, 슬래시 등 특수문자가 포함되면 `to_tsquery` 구문 오류 가능성도 있다.

### 결론

```text
사용자 원문 → FTS
```

경로는 사용하지 않는다.

FTS가 필요하다면:

```text
사용자 질문
   ↓
Intent 분석
   ↓
추출된 정확 용어
   ↓
FTS
```

형태로만 사용한다.

---

### 6.4 동의어 검색이 가장 취약하다

동의어 질의 결과:

```text
Top-1 Strict   4/10
Top-1 Lenient  5/10
Recall@3       8/10
```

대표 실패:

| 질의 | 1위 검색 결과 | 기대 결과 |
|---|---|---|
| 채권 이자율 | 매수수익률 0.5841 | 표면금리 0.5542 |
| 보수율 | 매수수익률 0.5099 | 총보수요율 0.4973 |
| 펀드 규모 | 공모펀드 0.5889 | 순자산총액 0.5700 |
| 구성종목 | 기초지수 추종 0.4904 | 편입증권 Top-10 밖 |

특히 `채권 이자율`은 10건 합성 코퍼스에서는 표면금리가 1위였으나, 실제 130건에서는 경쟁 용어인 `매수수익률`이 추가되면서 결과가 뒤집혔다.

### 결론

향후 검색사전 품질 개선의 우선순위는 단순 threshold 조정이 아니라:

- `skos:altLabel` 보강
- comment 내 개념 구분 설명 강화
- entity type / domain / range 활용

이다.

---

### 6.5 `BOND_SCORE_FLOOR = 0.45`는 관련성 판정 기준이 아니다

무관 질의 8건 중 2건이 0.45를 초과했다.

```text
"파이썬 리스트 정렬하는 방법"
→ 신용등급 0.4888

"비트코인 시세 알려줘"
→ 발행시장 0.4853
```

반대로 실제 관련 질의에서도:

```text
"보수"
→ 총보수요율 0.401
```

처럼 0.45보다 낮은 정답이 존재했다.

또한 온톨로지에 없는 질의:

```text
"만기수익률 YTM이 얼마인가요"
→ 연초이후 수익률 0.582
```

처럼 높은 점수의 잘못된 유사 개념이 반환될 수 있다.

### 결론

`0.45`는 검색 결과의 극단적인 노이즈를 줄이는 **noise floor**로만 사용한다.

```text
score >= 0.45
≠
질의가 ontology에서 답변 가능함
```

답변 가능 여부는 별도 TBox / Intent Validation 단계에서 판정한다.

## 7. 130 Baseline에서 확정할 검색 정책

현재 결과를 기준으로 다음 정책을 baseline으로 고정한다.

```text
User Question
      ↓
Intent Analysis
      ↓
Vector Search
      ↓
Top-3 후보
      ↓
Ontology Grounding
      ↓
TBox / Intent Validation
      ↓
RDB Query / Answer
```

검색 정책:

1. Vector Search를 주 검색기로 사용한다.
2. Top-1이 아니라 Top-3를 grounding 후보로 전달한다.
3. RRF Hybrid Search는 기본 경로에서 제외한다.
4. FTS는 사용자 원문이 아니라 Intent에서 추출된 정확 용어에만 선택적으로 사용한다.
5. `BOND_SCORE_FLOOR = 0.45`는 noise floor로 유지한다.
6. Unsupported 판정을 similarity score에 맡기지 않는다.

## 9. 현재 Baseline이 검증하지 않은 것

이번 테스트 결과를 과도하게 해석하지 않기 위해 다음 범위는 미검증으로 남긴다.

### 9.1 LLM 답변 정확도

이번 테스트는 검색 결과만 평가했다.

```text
질의
→ 올바른 ontology 후보 검색
```

까지만 검증했으며, HyperCLOVA X가 이 후보를 받아 최종적으로 올바른 답변 또는 SQL 조건을 생성하는지는 별도 E2E 테스트가 필요하다.

### 9.2 Gold 정답의 객관성

72개 질의의 gold URI는 테스트 설계자가 지정했다.

특히 동일 label을 갖는 클래스/프로퍼티 및 혼동군에서는 정답 선택에 판단이 포함될 수 있으므로 strict와 lenient 결과를 함께 유지한다.

### 9.3 누락 코드리스트 91건

현재 검색사전에는 `rdfs:comment`가 없는 코드리스트 개체 91건이 빠져 있다.

예:

- 신용등급 값
- 투자지역
- 자산군
- 위험등급
- 만기구분
- 담보유형

따라서 130 baseline은 최종 검색사전 성능이 아니라 **221개 확장 전 비교 기준선**이다.

## 11. 한 문장 결론

> 실제 130개 온톨로지에서는 Top-1 정확도보다 Top-3 Recall이 훨씬 안정적이며, Vector Search를 주 검색기로 사용하고 Top-3 후보를 후속 grounding/validation에 전달하는 구조가 현재 가장 타당하다.
