## 1. 전체 결론

현재까지 확인된 것은 다음과 같다.

1. pgvector 기반 TBox 검색 인프라는 동작한다.
2. TBox 의미 검색은 Top-1보다 Top-3 후보 전달이 적합하며, 코드리스트를 같은 인덱스에 섞으면 품질과 evidence가 하락한다.
3. HCX Query Frame v1은 JSON 구조와 일부 핵심 의미는 보존하지만, constraint·relation·computation 정확도와 latency가 운영 기준에 미달한다.
4. LLM에 전체 physical schema와 설명을 주고 자유롭게 SQL·route를 생성시키는 방식은 실패했다.
5. 저장 Query Frame 이후 deterministic RDB compiler·PostgreSQL 실행은 Gold 14/14로 성공했다.
6. 실시간 HCX를 포함하면 429·timeout·q006 entity 해석 문제로 운영 안정성은 아직 실패다.
7. pyoxigraph GRAPH_ONLY vertical slice와 문서 evidence 계약은 성공했다.
8. RDB·Graph·Vector를 모두 연결한 전체 Agent E2E와 Vector content retrieval은 아직 구현·검증되지 않았다.
9. 현재 RDB snapshot은 2026-08-21이므로 대회 cutoff 2026-07-11 기준의 운영 승격에는 사용할 수 없다.

## 3. 실험 1 — pgvector 기본 검증

원문: [`1_result_pgvector_test.md`](1_pgvector_test/1_result_pgvector_test.md)

### 측정 결과

- PostgreSQL 18.6, pgvector 0.8.1, `bge-m3` 1024차원 cosine 구성
- 연결·스키마·벡터·키워드·하이브리드·통합 테스트 `6/6 PASS`
- 10문서·7질의 소규모 환경에서 벡터 및 하이브리드 Top-1 `7/7`
- FAISS와 pgvector cosine 최대 오차 `5.03e-07`, Top-5 순서 동일
- 한국어 FTS는 6질의 중 3건만 적중했다. 조사 결합·부분어·동의어는 실패했다.

### 해석

pgvector 이전 가능성은 확인됐지만, 10문서 결과는 검색 품질을 대표하지 않는다. 벡터를 주 검색기로 사용하고 FTS는 정확 용어 보조로만 사용해야 한다.

### 미측정

- 실제 전체 TBox 경쟁 환경
- Agent 최종 답변 정확도
- 대규모 인덱스의 HNSW 성능

## 4. 실험 2 — 실제 TBox 130건 검색 Baseline

원문: [`2_eval130.md`](2_baseline_130_v1/results/2_eval130.md)

### 측정 결과

| 지표 | 결과 |
|---|---:|
| Strict Top-1 | `39/52`, 75.0% |
| Lenient Top-1 | `51/60`, 85.0% |

| 무관 질의의 0.45 초과 오탐 | `2/8`, 25.0% |

1·2위 점수 차이가 0.02 미만인 질의가 `18/60`, 30%였다. 하이브리드는 벡터 단독보다 한 건 낮았고, 원문 질문을 FTS AND로 검색하면 예상 35문항 모두 0건이었다.

### 결정

- TBox grounding은 Top-1 한 건이 아니라 Top-3 후보를 전달한다.

- FTS에는 원문 질문이 아니라 추출된 용어만 넣는다.
- `BOND_SCORE_FLOOR=0.45`는 노이즈 컷이며 답변불가 판정 기준으로 사용하지 않는다.

### 미측정

- Top-3 후보를 받은 Planner의 최종 선택 정확도
- 실제 Answer 생성 품질
