# 답변불가 판정 규칙 배선 초안 (2026-08-22)

> 생성물 — `python3 script/build_abstain_rules.py` 로 재생성. 산출: `ABSTAIN_RULES.csv` (18규칙)
> 입력: [PROPERTY_STORAGE_MAP.md](PROPERTY_STORAGE_MAP.md) · 트리거 어휘는 손으로 작성

## 무엇을 푸는가

`storage=none` 9속성과 `domain_caveat` 9건은 "답할 수 없다"는 사실이 **데이터에 이미 적혀
있는데** 라우터가 그걸 못 읽는다. 그래서 검색을 돌리고 0행을 받고 "해당 상품이 없습니다"라고
답한다. **상품은 있는데 우리가 판별을 못 하는 것**이므로 이건 사실과 다른 답이다.

이 표는 그 18건을 **검색 전에 판정하는 규칙**으로 바꾼다. 걸리면 엔진 호출도 LLM 호출도 없다.

## action 3종

| action | 뜻 | 개수 |
|---|---|---:|
| `ABSTAIN` | 검색 없이 즉시 답변불가 | 8 |
| `GUARD` | **해당 도메인만** 잘라내고 나머지는 정상 답변 | 9 |
| `REWRITE` | 다른 경로로 우회 가능 — 답변불가로 처리하면 **오답** | 1 |

`GUARD`가 핵심이다. "위험등급 3 이하 ETF"는 국내ETF로는 답할 수 있고 해외ETF로는 답할 수
없다. 전부 답변불가로 처리하면 답할 수 있는 질문을 버리고, 조용히 국내만 답하면 해외 5,646종이
사라진 사실이 드러나지 않는다. **부분 답변 + 제외 사유 명시**가 정답이다.

`REWRITE` 1건은 `fp:subsidiaryOf`다. 인스턴스는 0건이지만 `fp:hasSubsidiary` 역방향
탐색으로 우회된다(관계 29,524행 보유). 매핑표만 보고 `none`이라고 답변불가 처리하면
**"에코프로의 모회사" 같은 질의를 놓친다.**

## 🔴 ABSTAIN 코드 6종이 필요하다 — 기존 5종으로 안 덮인다

현행 5종(`docs/agent-spec-0821.md:127`): `INVALID_TAXONOMY` / `AFTER_AS_OF` /
`NOT_FOUND` / `FUTURE_VALUE` / `DOMAIN_VIOLATION`

**"월배당 ETF 알려줘"를 넣어보면 어디에도 안 맞는다:**

| 코드 | 맞나 | 왜 아닌가 |
|---|---|---|
| `INVALID_TAXONOMY` | ✗ | '분배 유형'은 온톨로지에 정상 선언된 개념이다 |
| `NOT_FOUND` | ✗ | **월배당 ETF는 실재할 수 있다.** 우리가 판별을 못 할 뿐이다 |
| `DOMAIN_VIOLATION` | ✗ | `fp:hasDistributionType`의 domain은 ETF다. 위반이 아니다 |
| `AFTER_AS_OF` / `FUTURE_VALUE` | ✗ | 시점과 무관하다 |

→ **`AXIS_UNAVAILABLE`(측정 축 부재)을 6번째 코드로 제안한다.** 15규칙이 여기 해당한다.

이게 왜 중요하냐면 — `NOT_FOUND`로 뭉뚱그리면 답변이 **"그런 상품이 없습니다"**가 된다.
사실이 아니다. 주최측 채점은 "확인할 수 없음" 명시면 정답 처리하지만, **`think_trace`가
필수 필드라 틀린 추론 과정이 그대로 노출된다.** AGENTS.md 규칙 4의 "답변불가 판정은 사유를
구분한다"도 이걸 요구한다.

> 코드 추가는 스펙 변경이라 **제안만 한다.** 채택 여부는 스펙 소유자가 정한다.
> 채택하지 않으려면 15규칙을 `NOT_FOUND`로 접어야 하며, 위 부작용을 감수하는 선택이다.

## 평가 순서

앞의 3단계는 **검색 이전**이라 비용이 0이다.

```
1. Family A (ABSTAIN)          ← 트리거 매칭. 엔진 호출 없음
2. DOMAIN_VIOLATION            ← TBox domain/range ASK. "VOO가 발행한 채권"
3. INVALID_TAXONOMY            ← 허용값 집합 대조. "AAAA 등급"
── 여기까지 통과하면 도메인 확정 ──
4. Family B (GUARD)            ← 확정된 도메인에서 무효 축이면 그 도메인만 제외
5. 검색 실행
6. NOT_FOUND / AFTER_AS_OF / FUTURE_VALUE   ← 0행 확인 후
```

## 공식 답변불가 예시 3문항 매핑

| 공식 질의 | 코드 | 판정 근거 | 상태 |
|---|---|---|---|
| 신용등급 AAAA인 채권 | `INVALID_TAXONOMY` | `CRD_GRD` 허용값 21종에 `AAAA` 부재 | ✅ 동작 |
| KODEX AI로봇 ETF | `NOT_FOUND` | 완전일치 0건. **유사명 18건이라 완전일치 우선 규칙 필수** | ✅ 동작 |
| Kimi 관련 투자 상품 | `NOT_FOUND` ↔ `AFTER_AS_OF` | 전 도메인 0건(편입 47,016행 포함). **둘 중 어느 사유인지 가릴 근거 없음** | ⚠ 사유 오분류 위험 |

Kimi 건은 **AI 모델 출시일 레퍼런스**가 있어야 `AFTER_AS_OF`로 확정된다. 없으면 `NOT_FOUND`로
답하게 되는데, 채점은 통과하더라도 `think_trace`에 틀린 사유가 남는다.
`PD_ENG_NM='KIMIELECTRONICS7/8'` **2건 오탐**도 완전일치 규칙으로 막아야 한다.

## 트리거 어휘 — 83개, 그리고 이건 TBox에 들어가야 한다

**속성 레벨 `skos:altLabel`이 0건이다**(2026-08-22 실측, altLabel 트리플 67개는 전부
코드값 개체에 달려 있다). `rdfs:label`은 표준명 1개뿐이라 "월배당"·"곱버스" 같은 질의
표층형을 `fp:hasDistributionType`·`fp:leverageFactor`로 이을 사전이 없다.

`ABSTAIN_RULES.csv`의 `trigger_ko` 83개는 그 공백을 임시로 메우는 것이고, **그대로 TBox
`skos:altLabel` 보강 후보다.** TTL에 들어가면 2단계 스키마 검색이 임베딩으로 잡으므로
키워드 매칭보다 견고해진다. `research/온톨로지_그라운딩_리서치.md`가 SKOS를 "이기종 용어
표준화가 여기서 해결됨"이라고 정리한 지점이 정확히 이것이다.

## 한계 — 키워드 매칭의 오탐

`trigger_ko`는 현재 **문자열 포함 매칭**을 전제한다. Family B는 도메인이 확정된 뒤에만
평가되므로 범위가 좁지만, **Family A는 오탐 여지가 있다.**

- `담보` → "담보대출 관련 채권"처럼 다른 맥락에서 등장할 수 있다
- `수탁` → "수탁고"(=수탁자산 규모)는 전혀 다른 개념이다
- `배당` → 개별 주식의 배당이 화제일 수 있다

**즉시 ABSTAIN하기 전에 그라운딩 결과로 한 번 확인하는 단계를 두는 것이 안전하다.**
답변불가를 잘못 내면 답할 수 있는 문항을 버리는 것이고, 이건 감점 방어의 반대 방향이다.
