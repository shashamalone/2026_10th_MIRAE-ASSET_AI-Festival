## 1. 선정 기준 — 온톨로지 등급 4값 정의

온톨로지(.ttl) 설계 시 각 컬럼을 다음 4등급 중 하나로 판정한다. 판정은 "이 컬럼이 없으면 어떤 질의가 깨지는가"를 기준으로 하며, 데이터 품질(결측률·상수 여부)은 등급을 낮추는 요인이지만 등급을 결정하는 유일 요인은 아니다. 결측이 높아도 질의 빈출 축이면 `필수-조건`으로 두고 `외부보완` 열에 보강 경로를 명시한다.

### 필수-식별 (Identity)

**정의** — 엔티티 URI를 구성하거나 엔티티를 사람이 지목하는 데 쓰이는 컬럼. 클래스 인스턴스 1개당 1값으로 확정되어야 하며, `owl:InverseFunctionalProperty` 또는 `rdfs:label` / `skos:prefLabel`로 매핑된다.

**판정 규칙**
1. 도메인 그레인 상 유일성이 실측으로 확인될 것 (중복 0건).
2. 유일성이 깨지는 식별자는 URI 소재로 쓰지 않고 **외부 조인키(= 필수-관계)로 강등**한다.
3. 복합키가 그레인인 도메인은 구성 컬럼 전부를 `필수-식별`로 둔다.

**대상** — `bond_kr.PD_NO`(중복 0), `etf_kr.pd_itm_no` / `pd_itm_no_ma`, `etf_gl.pd_itm_no`, `fund_pub.(itm_no, prfd_attr_cd)` 복합키 및 `std_itm_no`. 상품명·약어명은 URI가 아니라 레이블 축으로서 `필수-식별`에 포함한다(자연어 질의가 상품을 지목하는 유일한 통로이기 때문).

**반례(강등)** — `etf_gl.pd_isin_cd`는 국제 표준코드지만 티커 변경 잔재로 **50종이 중복**하므로 유일키로 쓰지 않고 `필수-관계`(외부 조인키)로 강등한다.

### 필수-조건 (Qualifier)

**정의** — 자연어 질의의 **필터 조건·정렬 축·비교 기준**으로 직접 소비되는 속성. `owl:DatatypeProperty`로 모델링하고, 코드값은 `skos:Concept` 스킴으로 승격해 도메인 간 서열 통합의 근거로 삼는다.

**판정 규칙**
1. "~이상/이하", "~인 것만", "가장 ~한" 형태 질의에서 술어로 쓰일 수 있을 것.
2. 값 도메인이 유한 코드이거나(등급·자산군·지역) 순서형 수치일 것(보수율·순자산·잔존만기).
3. 결측률이 높아도 대체 불가한 축이면 유지하되 `외부보완`을 필수 표기한다.
4. **전 행 동일값(상수)·전 행 미계산(0.00)은 필터로 기능하지 못하므로 제외 대상**이다.

**대상 축(도메인 공통)** — 신용등급, 잔존만기·듀레이션, 총보수, 순자산·AUM, 위험등급, 자산군, 투자지역, 레버리지 배수, 인버스 여부, 환헤지, 판매여부, 상장/폐지일, 기간별 수익률.

**서열 통합 예시** — `etf_kr.pd_risk_cd`(1~6등급)와 `fund_pub.zrin_fd_ivst_risk_gcd`(1~6)는 방향이 반대다. ETF는 코드 11이 "매우높은위험(1등급)", 펀드는 코드 1이 "매우 높은 위험"으로 **둘 다 숫자 1이 최고위험**이라 서열 축 하나로 통합 가능하다. 다만 `etf_kr`은 `PD_RISK_GCD_1x` 접두를 벗겨야 한다.

### 필수-관계 (Relation)

**정의** — 값 자체가 아니라 **다른 엔티티를 가리키는** 컬럼. `owl:ObjectProperty`의 range를 별도 클래스(운용사·발행사·지수·모펀드·외부 식별자)로 두고, 문자열은 그 클래스 인스턴스의 레이블로 정규화한다.

**판정 규칙**
1. 값이 다른 상품·기관·지수·기업을 지시할 것.
2. 도메인 간 조인 또는 외부 데이터 조인의 열쇠일 것.
3. 유일성이 깨진 식별자, 분류체계 코드도 여기에 포함한다(엔티티를 가리키되 URI가 되지는 못하는 경우).

**대상** — 운용사(`cu_fund_mgmt_co`, `or_co_xtn_itt_cd`), 발행사(`PD_PBCM`), 기초지수/벤치마크(`cu_base_index`, `bmrk_nm`), 모펀드·클래스 그룹(`mtco_itm_no`, `rptt_ksd_itm_no`), 외부 조인키(`pd_us_cik`, `pd_lipper_id`, `pd_isin_cd`, `fss_itm_no`, `ksd_itm_no`), 분류체계(`kofia_fd_ccd`), 수탁사(`trusc_xtn_itt_cd`).

**설계 주의** — 관계 컬럼은 대부분 **문자열 표기 흔들림**이 있다. `etf_kr.cu_fund_mgmt_co`는 '한국투자' / '한국투자증권(주)' / '엔에이치투자증권(주)' / 'NH-Amundi'가 공존해 고유 97종이지만 실제 기관 수는 그보다 적다. 정규화 사전과 `skos:altLabel`이 필수다.

### 보조/제외 (Auxiliary / Excluded)

**정의** — 온톨로지 클래스 속성으로 승격하지 않거나, 승격하되 질의 축으로 노출하지 않는 컬럼. .ttl에는 싣지 않고 필요 시 원본 레코드 링크로만 남긴다.

**판정 규칙(하나라도 해당 시)**
1. **시세·파생 지표** — 종가·고가·시가·거래량·거래대금·기준가·괴리율 등 스냅샷 시점 값. 온톨로지는 시점 불변 사실을 담고 시세는 원천 테이블 참조로 처리한다.
2. **내부 관리 코드·적재 메타** — 갱신일자, 적재 테이블명(`du_clpr_src = 'pd65n101.tday_clpr'`), 사내 코드.
3. **결측 90% 이상** — 대체 축이 존재하는 경우에 한해 제외(대체 불가면 `필수-조건` + `외부보완`).
4. **상수 컬럼(고유값 1종)** — 필터로 기능 불가.
5. **완전 중복 컬럼** — 다른 컬럼과 1:1 대응. 예: `etf_gl.cu_etn_yn`은 `pd_grp_no=='ETN'`과 **5,646행 전부 일치**하고, `etf_gl.pd_itm_no_ma`는 `pd_itm_no`와 전 행 동일하며, `fund_pub.frc_bpr_itm_yn`은 `curr_cd=='USD'`와 완전 일치한다.

## 3. 도메인 공통 주의사항

### 3.0 전 도메인 공통

1. **파일명 날짜(20260711)는 데이터 기준일이 아니다.** 도메인별 실질 기준일이 모두 다르다.
   | 도메인 | 실질 기준일 | 근거 컬럼 |
   |---|---|---|
   | bond_kr | **2026-02-24** | `PD_STD_INFO_UPDATE` 최빈값 20,160건 |
   | etf_kr | **2026-06-15** (시세) / 2026-06-15 (주간) | `du_upt_dt` 전량 상수, `wu_upt_dt` |
   | etf_gl | **2026-06-14** (NAV) / 종가는 종목별 상이 | `du_nav_base_dt` 상수, `du_clpr_base_dt` 86종 분산 |
   | fund_pub | 미표기 | 기준일 컬럼 자체가 없음 |
   기준일이 4개월 이상 벌어지므로 **도메인 간 수익률·순자산 직접 비교는 시점 주석을 반드시 동반**해야 한다.
2. **결측은 NULL이 아니라 빈 문자열('')로 적재되어 있다.** `pd.read_csv(..., keep_default_na=False)` 없이 읽으면 `'NA'`, `'N/A'` 같은 정상값이 결측으로 오인될 수 있다.
3. **sentinel 값이 결측을 위장한다.** 컬럼별 sentinel: `0`·`99991231`(bond 일자), `0.0`(etf_kr 총보수), `Index is not provided by…`(etf_gl 기초지수), `000000000000`·`KR0000000000`·`0*20`(fund_pub 코드). **`isnull()`만으로 결측 판정 시 전부 유효값으로 집계된다.**
4. **`고유값 1종` 컬럼은 온톨로지에서 제외한다.** 207컬럼 중 유효 고유값이 1종 이하(상수 또는 전량 결측)인 컬럼이 **40개**(bond_kr 1, etf_kr 22, etf_gl 15, fund_pub 2)로 전체의 **19.3%**다. 그중 값이 아예 없는 빈 컬럼이 7개(etf_kr 6, etf_gl 1)다.
5. **위험등급 서열 방향은 세 도메인 모두 "숫자 1 = 최고위험"으로 일치**한다(bond `PD_RISK_GCD`, etf_kr `pd_risk_cd` 끝자리, fund_pub `zrin_fd_ivst_risk_gcd`). 단일 `RiskGrade` 스킴으로 통합 가능하다.

### 3.1 bond_kr

- **아카이브 혼재**: 만기일이 실질 기준일(2026-02-24) 이전인 종목이 **11,940건(28.2%)**, 파일명 날짜(2026-07-11) 기준으로는 **16,180건(38.2%)**이다. "지금 살 수 있는 채권" 질의는 반드시 만기 필터를 선행해야 한다.

- **`DUR == 0`이 8,268건**으로, 미계산과 만기경과가 섞여 있다. 듀레이션 질의 시 0 제외 필수.

- **`cu_strtegy`는 enum이 아니다.** 국내 ETF의 동명 컬럼(4값 코드)과 달리 **평균 309자의 서술형 투자전략 문단**이며 고유값 5,566종(결측 0.1%)이다. 정형 필터로는 쓸 수 없고 **벡터 인덱싱해 RAG 근거 텍스트로 소비**해야 한다. 반대로 테마·전략 질의의 근거로는 4개 도메인 통틀어 가장 풍부한 자산이다.
- **총보수 결측 0%** — 국내 ETF(81.9%)와 정반대다. 해외 ETF는 보수 기반 질의를 온전히 지원할 수 있다.
- **ISIN 중복 50종**(`pd_isin_cd`). 티커 변경 후 구 레코드가 남은 잔재로 보이며, `pd_lipper_id`도 동일하게 50건 중복한다. **ISIN을 유일키로 쓰면 안 되고**, URI는 `pd_itm_no`(중복 0)로 구성한 뒤 ISIN은 외부 조인 속성으로만 둔다.
- **CIK만으로 개별 ETF를 특정할 수 없다.** `pd_us_cik` 고유 374종에 5,633행이 물려 있고 한 CIK가 최대 380개 상품을 가진다(운용사 트러스트 단위 등록). N-PORT 구성종목을 개별 ETF로 귀속하려면 **Series ID가 추가로 필요**하며, 이것이 해외 holdings 확보의 실제 병목이다.
- **`cu_lev_fector` 전량 결측.** 레버리지 배수 질의는 `pd_nm`/`cu_strtegy` 텍스트 파싱(`2X`, `3X`, `Ultra`, `Bear` 등)으로만 대응 가능하다. 인버스는 `cu_inverse_short_yn`(Y 171건)이 유일한 정형축이다.
- **거래소코드 오염 31건**: `pd_exg_mkt_cd`에 알파벳 코드(AMX/NAS/NYS)와 숫자 코드(`102` 22건, `101` 9건)가 혼재한다. 거래소 필터 시 매핑 또는 제외 처리가 필요하다.
- **완전 중복 컬럼 3쌍**: `pd_itm_no_ma` ≡ `pd_itm_no`, `cu_etn_yn` ≡ `pd_grp_no=='ETN'`, `ru_mkt_volume` ≡ `du_vol_1d`. 온톨로지에 중복 적재하지 않는다.
- **판매·거래정지 축이 없다**: `pd_sale_yn`은 전량 `1`, `pd_tr_yn`은 전량 `0`, `wu_core_yn`은 `N`만 존재(`Y` 0건). 국내 ETF에는 있는 "핵심 상품", "판매 가능" 필터를 해외에는 적용할 수 없다.
- **수치 표기 `0E-8`**: `du_val_1d`, `du_vol_1d`, `pd_lst_price` 등에 지수 표기 0이 들어온다. 문자열 파싱 시 명시적 캐스팅 필요.
- **종가와 NAV의 기준일이 항상 다르다**(`du_base_dt_match_yn`이 전 행 `N`). 종가 기준일은 86종으로 분산돼 stale 종목이 섞여 있다.

### 3.4 fund_pub

- **롱포맷 그레인이 최대 함정이다.** 유일키는 `(itm_no, prfd_attr_cd)` 복합키(중복 0건)이며, 실제 펀드는 **11,139종**인데 행은 95,619개로 **평균 8.58배**다. 중복제거 없이 `fd_nast_suma`를 합산하면 **13,194조원**이 나오지만 `itm_no` 기준 dedup 후에는 **1,546조원**으로, **8.54배 왜곡**된다. 모든 펀드 단위 집계는 `drop_duplicates('itm_no')` 선행이 필수다.
- **`prfd_attr_cd` 228종은 2체계 + 오염 1건이다.** ① 영문1자+숫자3자(`C103`, `M111` 등) **210종**, ② ISO 3166 3자리 국가코드(`CHN`, `USA`, `JPN`, `KOR`, `DEU`, `VNM` 등) **17종**, ③ `해외` **1종**. ③은 별도 체계가 아니라 아래 파싱 붕괴 행의 잔재다.
- **CSV 파싱이 붕괴한 행 1개**(0-based index 84561, `itm_no == '"'`)가 **여러 컬럼의 이상값을 동시에 만들어낸다.** 따옴표 처리 오류로 값이 좌우로 밀린 결과다.
  - `exchdg_yn = '00080008'` (기관코드가 밀려 들어옴)
  - `prfd_attr_cd = '해외'`
  - `thco_sale_yn = 'KRZ50226929C'` (예탁원 코드)
  - `zrin_fd_ivst_risk_gcd = '00020054'` (수탁사 코드)
  - `zrin_fd_ivst_risk_grd_nm = '06'`
  - `sale_yn = ''` (전체 유일한 결측)
  **이 1행만 제거하면 5개 컬럼의 이상 enum이 동시에 해소된다.** 개별 컬럼별로 예외 처리하지 말고 행 단위로 배제할 것.
- **`kofia_fd_ccd`의 `0` 20자리가 22,131행(23.1%)**이다. 유효값도 자리별 의미가 **역추정 가설 단계**이므로, 금투협 코드 부여기준 문서를 확보하기 전에는 분류 필터축으로 쓰면 안 된다. 길이 19자리 이상 행도 10건 있다.
- **`rptt_ksd_itm_no` sentinel**: `KR0000000000` 1,525행, `000000000000` 976행(합 2,501행, 2.6%). `fss_itm_no`도 `000000000000`이 **23,409행(24.5%)**으로 sentinel 비중이 훨씬 크다.
- **`mtco_itm_no`가 클래스→모펀드 그룹핑의 최적 키다.** 11,139종이 4,661그룹으로 수렴하며, 같은 그룹은 `미래에셋글로벌포커스4.0마켓헤지증권자투자신탁(H)(주식-파생형) 종류C1~C4`처럼 동일 모펀드의 클래스 집합이다. **단, 선행 `"` 65행과 길이 불균일(1~10자, 표준 7자)이 있어 `strip('"') + zfill(7)` 정규화가 선행되어야 한다.** `rptt_ksd_itm_no`(sentinel 2.6%)보다 신뢰도가 높다.
- **`or_attr_desc`의 `06` 5,436행은 오염이 아니다.** 다른 값이 모두 한글 설명(`주식형`, `채권형`…)인데 `06`만 원본 코드가 노출된 것으로, **파생형에 해당하는 미매핑 코드**다(펀드 단위 686종). `06 → 파생형` 매핑을 명시하고 사용한다.
- **위험등급명 공백 표기 흔들림**: `높은 위험`(29,088)과 `높은위험`(163), `보통 위험`(13,028)과 `보통위험`(75)이 병존한다. 공백 제거 정규화 후 코드(`zrin_fd_ivst_risk_gcd` 1~6)를 정본으로 삼는다.
- **`thco_sale_yn`에는 `N`이 없다.** `Y` 91,594행과 결측 4.2%뿐이므로 **결측을 "당사 미취급"으로 해석**해야 한다. 판매 상태 축은 `sale_yn`(판매중/판매완료)이 정본이다.
- **수익률이 전 구간 결측인 펀드가 3,536종**(11,139종의 31.7%)이다. 대부분 `판매완료` 상태의 잔존 레코드로, 성과 랭킹 질의 시 자동 배제된다. 반대로 "판매완료 펀드도 포함" 질의는 답변 근거가 없다.
- **`std_itm_no`는 두 형식이 혼재**한다(`KR5…`와 `K55…`). 펀드 단위 중복 11건, 결측 66행이 있어 `itm_no`를 정본 식별자로 두고 `std_itm_no`는 보조 식별자로 병기한다.
