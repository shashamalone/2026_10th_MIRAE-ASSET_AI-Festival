# 국내 ETF 편입종목 수집 설계

EXTERNAL_DATA_PLAN의 **P0-2(국내 ETF 편입종목, blocking 7문항)** 취득 설계. 4대 운용사 정찰(2026-08-13) 결과에 근거한다.

## 1. 정찰 결과 요약

4개 브랜드 전부 **공개 접근 가능, 인증 불필요, robots.txt 허용, 과거 일자 조회 가능**. 계획서 4.1이 우려한 3대 난관(PDF 표 파싱 / 아카이브 부재 / 종목 수 부담)은 전부 해소됐다.

| 항목 | KODEX(삼성) | TIGER(미래에셋) | RISE(KB) | ACE(한국투자) |
|---|---|---|---|---|
| 응답 형식 | JSON + 진짜 xls | HTML `<tr>` 조각 | HTML table(.xls 위장) | JSON |
| ETF 식별 키 | 내부 `fId` | **ISIN 직결** | 내부 4자리 ID | 내부 `fundCd` |
| 키 매핑 비용 | 목록 API 12페이지 | **불필요** | 목록 24페이지(~10초) | 목록 1회 호출 |
| 편입종목 식별자 | 6자리 티커(xls엔 ISIN) | 6자리 티커 / 해외는 블룸버그 | **ISIN 12자리** | 6자리 / 블룸버그 / ISIN 혼재 |
| 과거 이력 | 2020~ | **2009~** | 2020~ | 2022~ |
| **룩어헤드 오염** | **현재가·등락 2컬럼** | **등락률 1컬럼** | 없음 | 없음 |
| 무효 컬럼 | — | — | 평가금액 항상 `-` | — |
| 속도 | 0.2초/종 | **0.15초/종** | 0.15초/종 | 0.32초/종 |
| 매핑 성공 | 237/240 | 229/235 | 140/147 | 106/114 |

**as_of = 2026-07-10 확정.** 2026-07-11은 토요일이라 4개 사이트 모두 데이터가 없다. 대회 기준일 이전이면서 가장 가까운 영업일이다.

## 3. 수집 스크립트 설계

### 3.1 어댑터 구조

브랜드마다 응답 형식·키 체계가 달라 공통화가 불가능한 부분은 **함수 3개로 격리**하고, 나머지 파이프라인은 공유한다.

```
브랜드별 어댑터 (3함수)
  list_products()        → {ISIN: 내부ID}     # TIGER는 항등 함수
  fetch(내부ID, as_of)   → bytes (원본 그대로)
  parse(bytes)           → [(code, name, weight, qty), ...]

공통 파이프라인
  ① 원본 저장 + 사이드카 .meta.json  (data/external/etf_kr_holdings/)
  ② 룩어헤드 컬럼 드롭
  ③ 식별자 정규화
  ④ data/relations/etf_holding.csv 병합 출력
  ⑤ validate_external.py → as_of 가드
```

어댑터는 dict 하나로 등록한다. 클래스 계층이나 플러그인 레지스트리는 만들지 않는다 — 브랜드 4개뿐이다.

### 3.2 출력 스키마

`data/relations/etf_holding.csv` (DATA_LAYER_PLAN 관계 테이블 규칙: 주어ID·목적어·source·as_of 필수)

| 컬럼 | 내용 |
|---|---|
| `pd_itm_no` | ETF ISIN (주어, 주최측 마스터 조인키) |
| `holding_code_raw` | 운용사가 준 원본 식별자 (가공 없이 보존) |
| `holding_code_type` | `ticker6` / `isin` / `bloomberg` / `other` |
| `holding_name` | 종목명 |
| `weight` | 비중(%) |
| `source` | `KODEX` / `TIGER` / `RISE` / `ACE` |
| `as_of` | `2026-07-10` |

수량·평가금액은 **싣지 않는다.** 브랜드마다 정의가 갈리고(CU당 수량 vs 실제 보유량), RISE는 평가금액이 아예 없으며, 질의가 요구하는 것은 비중이다. 필요해지면 그때 추가한다.

### 3.3 반드시 드롭할 컬럼 (룩어헤드)

| 브랜드 | 컬럼 | 근거 |
|---|---|---|
| KODEX | `curp`(현재가), `risep`(등락) | 2020·2025·2026 조회 모두 동일 값 = 오늘 값 고정 |
| TIGER | 등락률 | 한 달 간격 두 조회에서 200/200종 완전 동일 |

대회 규칙상 미래정보 유출이므로 **원본 파일에는 남기되 관계 테이블에는 절대 넣지 않는다**. as-of 주가가 필요하면 KODEX는 `평가금액÷수량`으로 파생 가능하다(실제 과거 주가와 일치 검증됨).

### 3.4 식별자 정규화 — 최대 쟁점

편입종목 식별자가 4가지 형식으로 섞인다. **정찰이 EXTERNAL_DATA_PLAN의 "기업 식별자 마스터 P0(enabler)" 판단을 실증했다** — 이 마스터 없이는 브랜드 간 편입종목을 같은 기업으로 묶을 수 없다.

당장은 `holding_code_raw` + `holding_code_type`으로 **원본을 보존만** 하고, 기업 마스터 확보 후 별도 `build_*.py`에서 `holding_key`를 채운다. 지금 추측으로 변환하면 잘못된 매핑이 굳는다.

- 국내주식: 6자리 티커 ↔ ISIN(KR7…)은 기업 마스터로 1:1 매핑
- 해외주식: 블룸버그 형식(`NVDA US EQUITY`, `NVDA US`)은 티커 추출 후 별도 매핑
- 국내채권·기타: ACE 자체코드(`03502G`) 등은 매핑 보류

### 3.5 생존편향 (반드시 문서화)

4개 브랜드 모두 **2026-07-11 이후 상장폐지된 종목을 사이트에서 제거**해, 과거 일자로 조회해도 0행이다.

| 브랜드 | 결손 | 성격 |
|---|---|---|
| KODEX | 3종 | 만기도래 채권 ETF |
| TIGER | 6종 | 상폐·만기 |
| RISE | 7종 | 2025년 중 상폐 |
| ACE | 8종 | 상폐 3 + 사이트 미노출 5 |

합계 24종. **스냅샷 시점에는 존재했으나 수집 불가**이므로, 답변 시 "편입종목 미확보 상품"으로 구분하고 없는 것을 없다고 답해야 한다. 조용히 빠지면 "그 ETF는 해당 종목을 편입하지 않았다"는 오답이 된다.

### 3.6 예상 소요

712종 × 평균 0.2초 + 0.3초 예의 지연 ≈ **6분**. 브랜드별 목록 매핑 포함해도 10분 이내.

## 4. 착수 순서

1. `EDA/collect_etf_holdings.py` 작성 (어댑터 4 + 공통 파이프라인)
2. 브랜드당 3종으로 시범 실행 → 파싱 정확도 확인
3. 712종 전량 수집 → `validate_external.py` 통과 확인
4. `build_etf_holding.py`로 관계 테이블 생성, `DATA_INVENTORY.md` 갱신
5. 미수집 24종 목록을 문서화

`EDA/collect_etf_holdings_pilot.py`(KRX/pykrx 경로)는 이 시점에 삭제한다 — KRX 무로그인 접근이 차단돼 더 이상 유효하지 않다. (2026-08-13 삭제 완료)

수집 중 확인된 원본 특성:
- RISE의 `CASH00000001 설정현금액`(142종 중 84종)은 편입종목이 아니라 CU 설정 단위이며 비중 100을 중복 계상한다 → parse에서 제외.
- RISE 채권 ETF는 종목명 셀이 비어 있어 빈 셀을 제거하면 컬럼이 밀린다 → 종목코드 위치를 앵커로 파싱.
- 비중 합계가 100±5를 벗어나는 67종은 대부분 레버리지·인버스·선물·합성(200%, -100%)이거나 커버드콜·FX스왑(음수 비중)으로 **원본 그대로가 정상**이다. 파싱 오류가 아니므로 관계 테이블에 포함한다.

## 6. 미수집 목록

답변 시 "편입종목 미확보 상품"으로 구분해야 하는 종목이다. 조용히 빠지면 "그 ETF는 해당 종목을 편입하지 않았다"는 오답이 된다(3.5).

### 6.1 KODEX 227종 — 차단(복구 가능)

수집 도중 samsungfund.com이 Cloudflare JS 챌린지(`429 Just a moment...`)를 걸었고, 이후 목록 API까지 도메인 전체가 차단됐다. 시간 간격을 두고 재시도하면 복구된다.

```
COLLECT_SLEEP=2 python3 EDA/collect_etf_holdings.py KODEX   # 받은 파일은 자동으로 건너뛴다
python3 EDA/build_etf_holding.py
```

미수집 티커는 `EDA/build_etf_holding.py` 실행 시 브랜드별 건수로 출력된다(전체 목록은 `data/external/etf_kr_holdings/`에 파일이 없는 종목).
