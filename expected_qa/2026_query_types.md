# 2026 금융상품 예상 평가 질문 유형 및 근거 설계

## 파일 목적

`2026_expected_queries.csv`는 국내채권, 국내 ETF, 해외 ETF, 국내 공모펀드를 대상으로 한 예상 평가 질문 35개를 정리한다.

- 답변 가능: 30개
- 답변 불가능: 5개
- 난이도: 하 10개, 중 10개, 상 10개와 답변 불가능 5개
- 평가 방식: 모든 문항 `PASS_OR_FAIL`
- 데이터 기준일: 2026-07-11

원본 `*_master_*`는 읽지 않고 `*_schema_*`, `*_axis_sample_*`에서 확인한 컬럼과 대표 엔티티를 기준으로 설계했다.

## 질문 유형

### 1. 단순조회

하나의 상품을 식별한 뒤 상품 속성이나 특정 시점의 수치를 조회한다. 작년 `simple_queries.csv`에 대응한다.

- 주요 처리: 상품명·티커·ISIN·상품번호 엔티티 해소, 최신 스냅샷 선택
- 우선 DB: RDB
- 대표 속성: 가격, NAV, AUM, 수익률, 만기, 금리, 위험등급, 판매 여부
- 답변 근거: 상품 식별자, 사용 컬럼, 수치 기준일 또는 갱신일

### 2. 조건검색

상품 집합에 하나 이상의 조건을 적용하고 정렬·집계·비교한다. 작년 `conditional_queries.csv`에 대응한다.

- 주요 처리: 신용등급 서열화, 자산·지역·전략 분류 정규화, 단위 변환, 복합 조건과 순위 계산
- 우선 DB: Ontology + RDB
- 대표 조건: AA- 이상, 매수가능수량 0 초과, AUM 임계값, 판매·거래·연금 가능 여부, 수익률 순위
- 답변 근거: 조건식, 분류 경로, 단위, 기준일, 결과에 사용한 원본값

### 3. 관계·시그널 검색

여러 엔티티와 문서를 연결하거나 특정 기간에 발생한 관계 변화를 찾는다. 작년 `signal_queries.csv`를 이번 과제의 지식그래프 구조에 맞게 확장한 유형이다.

- 주요 처리: 다단계 그래프 탐색, 기간 필터, 문서 검색, SQL 수치 결합
- 우선 DB: Graph DB + Vector DB + RDB
- 대표 경로: `ETF→편입증권→기업→자회사→산업/테마→위험요인`
- 답변 근거: 그래프의 각 간선을 지지하는 문서, 문서명, 발행일, 근거 문장, 편입비중·AUM 기준일

## 최소 온톨로지 구조

### 핵심 노드

- `Product`, `Bond`, `ETF`, `PublicFund`, `ShareClass`
- `Issuer`, `AssetManager`, `Index`, `Security`, `Company`
- `Industry`, `Theme`, `Risk`, `Document`, `MetricSnapshot`

### 핵심 관계

- `ISSUED_BY`: 채권 → 발행사
- `MANAGED_BY`: ETF·펀드 → 운용사
- `TRACKS_INDEX`: ETF·펀드 → 지수
- `HOLDS`: ETF·펀드 → 편입증권; `weight`, `as_of` 포함
- `ISSUED_BY_COMPANY`: 편입증권 → 기업
- `SUBSIDIARY_OF`: 자회사 → 모회사
- `BELONGS_TO_INDUSTRY`: 기업 → 산업
- `RELATED_TO_THEME`: 상품·기업 → 테마; 관계일과 근거 포함
- `HAS_RISK`: 상품·기업·산업 → 위험요인
- `HAS_SHARE_CLASS`, `SAME_VEHICLE_AS`: 상품 중복과 클래스 관계
- `SUPPORTED_BY`: 주장 또는 관계 → 근거 문서

모든 시간 가변 관계에는 최소한 `as_of` 또는 `valid_from`, `valid_to`, `source_id`가 필요하다.

## DB별 역할과 페더레이티드 쿼리 순서

1. 온톨로지에서 질의 엔티티, 상품 유형, 관계 경로와 조건 의미를 확정한다.
2. RDB에서 상품 속성, 수치, 기준일, 조건검색 결과와 순위를 계산한다.
3. Graph DB에서 편입, 발행, 모자회사, 산업·테마 관계를 탐색한다.
4. Vector DB에서 관계와 위험요인을 지지하는 공시·운용보고서·정책자료 문장을 검색한다.
5. 모든 주장에 근거가 연결된 결과만 조합하고, 기준일이 다른 수치는 각각 표시한다.

## 답변 근거 계약

답변 가능한 문항은 질문문 자체에 다음 중 필요한 근거를 명시한다.

- 상품번호, 티커, ISIN 등 정규 식별자
- 수치의 기준일과 사용 컬럼
- 적용한 분류값과 신용등급 서열
- 그래프 탐색 경로와 관계별 출처
- 편입내역 기준일과 편입비중
- 문서명, 발행기관, 발행일과 근거 문장
- 비교·중복도·순위의 계산식

근거가 없는 관계는 답변에 포함하지 않는다. 검색 문서에 단순히 함께 언급되었다는 사실만으로 편입·모자회사·테마 관계를 확정하지 않는다.

## 답변 불가능 판정

다음 중 하나에 해당하면 답변 생성으로 넘기지 않고 `ABSTAIN`한다.

1. 질의값이 신용등급 등 허용된 분류체계에 존재하지 않는다.
2. 기준일 현재 대상 모델이나 상품이 출시되지 않았다.
3. 정확한 상품 엔티티 또는 공식 근거 문서를 찾을 수 없다.
4. 요청 시점이 데이터 기준일보다 미래여서 실현값이 없다.
5. 엔티티 유형이 관계의 도메인·레인지와 맞지 않는다.

## 데이터 사용 시 주의사항

- `현재`는 시스템 날짜가 아니라 레코드의 최신 갱신일 기준으로 해석한다.
- AA- 이상 검색은 `axis_creditRating=AAGrade`만으로 처리하지 않고 원본 `CRD_GRD`를 서열화한다.
- 공모펀드 표본에는 ETF도 포함되므로 대표종목번호와 상품번호를 이용해 중복을 제거한다.
- 국내 ETF의 `du_lpr`는 스키마의 한글 설명과 통상적인 필드 의미가 충돌하므로 데이터 사전 확인 전에는 시가 질의에 사용하지 않는다.
- ETF 편입종목, 기업 자회사, 테마 사건, 위험요인은 현재 상품 CSV에 없으므로 별도 그래프와 근거 문서 적재가 필요하다.
