# 2차 테스트 — 실제 온톨로지 130개 기준 검색 품질

실행일 2026-08-22 · 재현: `python3 eval130_load.py && python3 eval130_run.py && python3 eval130_fts35.py`

1차 테스트(`test_result.md`)는 **10건 합성 코퍼스**였다. 거기서 나온 "질의 7건 전부 1위 정답"은
**경쟁 용어가 없는 환경의 결과**다. 이 문서는 실제 130건에서 다시 잰 것이다.

## 0. 1차와 무엇이 달라졌나

| | 1차 | 2차 |
|---|---|---|
| 문서 | 10건 (한국어 5) | **130건** (실제 `artifacts/bond_terms.json`) |
| 질의 | 7건 | **72건** (6분류 + 온톨로지 부재 4) |
| 지표 | 1위 정답 여부 | **Top-1(엄격/관대) · Recall@3 · 0.45 오탐/누락** |
| 임베딩 | 신규 17회 | 문서 130건 **캐시 재사용, API 0회** / 질의 72건 |

## 1. 130건 환경에서 새로 드러난 구조

**레이블이 완전히 같은 용어 16쌍(32개).** 클래스와 그 ObjectProperty가 `rdfs:label`을 공유한다.

```
투자위험등급  fp:RiskGrade / fp:hasRiskGrade      복제방식  fp:ReplicationMethod / fp:hasReplicationMethod
운용사       fp:AssetManager / fp:managedBy       발행기관  fp:Issuer / fp:documentPublisher  ← 성격도 다름
```

검색이 둘을 가를 근거는 `rdfs:comment` 뿐이다. 그래서 Top-1을 **엄격/관대 두 가지로** 잰다.

**혼동군 규모** — `등급` 14개 · `수익률` 12개 · `발행` 13개 · `수치` 5개 · `만기` 4개.
1차에는 `등급` 계열이 2개뿐이었다.

## 2. 결과

답변가능 질의 60건 (gold 단일지정 52건). 벡터 검색 기준.

| 분류 | n | Top-1 엄격 | Top-1 관대 | R@3 관대 | 하이브리드 | FTS 적중 |
|---|---|---|---|---|---|---|
| 정확 용어 | 12 | **12/12** | 12/12 | 12/12 | 11/12 | 12/12 |
| 자연어 | 12 | 8/12 | 10/12 | **12/12** | 10/12 | **0/12** |
| 동의어 | 10 | **4/10** | 5/10 | 8/10 | 5/10 | 1/10 |
| 부분어 | 8 | — | 8/8 | 8/8 | 8/8 | 7/8 |
| 혼동군 | 18 | 15/18 | 16/18 | **18/18** | 16/18 | 15/18 |
| **합계** | **60** | **39/52 = 75.0%** | **51/60 = 85.0%** | **58/60 = 96.7%** | 50/60 = 83.3% | 35/60 = 58.3% |

```
Top-1 엄격  75.0%      Recall@3  96.7%      0.45 오탐(무관 질의)  2/8 = 25%
```

## 3. 가장 중요한 발견 — Top-1은 사실상 동전던지기다

**1위와 2위의 점수차 중앙값 0.0318, 최소 0.0001. 0.02 미만이 18/60(30%).**

질의 3건 중 1건은 1·2위가 거의 동점이다. Top-1 75%와 Recall@3 96.7%의 격차가 여기서 나온다.

→ **1위 하나만 넘기면 25%를 잃는다. 상위 3건을 넘기면 3.3%만 잃는다.**
  2단계 grounding은 Top-1이 아니라 **Top-3를 후보로 전달**해야 한다.

## 4. 1차 결론이 뒤집힌 것 — 하이브리드가 손해다

| | 벡터 단독 | 하이브리드(RRF) |
|---|---|---|
| Top-1 관대 | **51/60** | 50/60 |

정확 용어에서 12/12 → **11/12로 떨어졌다.** FTS가 엉뚱한 용어를 상위로 올려 RRF가 정답을 밀어냈다.
1차(10건)에서는 경쟁자가 없어 FTS가 항상 정답만 반환했기에 이 손해가 보이지 않았다.

→ **RRF를 기본 경로로 쓰지 않는다.** FTS는 쓰더라도 벡터 랭킹을 덮지 않는 방식이어야 한다.

## 5. 실제 평가 35문항의 FTS 실측

앞서 "35문항은 자연어라 FTS가 전멸할 것"이라 **추정**했다. 실측 결과:

```
plainto_tsquery(AND)  적중  0/35   (100% 무적중)
to_tsquery(OR)        적중 33/35
```

**원인은 토큰 불일치가 아니라 AND 결합이다.** `plainto_tsquery`는 어절을 전부 AND로 묶으므로,
`알려줘`·`제시해줘`처럼 문서에 없는 토큰 하나가 질의 전체를 0건으로 만든다.
(질문 #1의 토큰에는 `신용등급`·`표면금리`·`만기일`이 조사 없이 멀쩡히 들어 있다.)

그런데 OR로 바꾸면 정밀도가 무너진다.

```
#1 기대근거: 발행사·신용등급·표면금리·만기일
   OR 상위 : 신용등급 보유, 신용등급 상태, 지분율, 편입비중, 총보수요율   ← 뒤 3개가 노이즈
#2 기대근거: 발행일·만기일·잔존일수·표면금리
   OR 상위 : 문서 발행일(오답), 신용등급 표기, 신용등급 상태
```

`상품`은 130건 중 16건, `함께`는 9건을 매칭한다. 또 `to_tsquery`에 원문 토큰을 그대로 넣으면
상품명의 `(`·`/` 때문에 **구문 오류로 죽는다**(`현대해상화재보험7(후)(콜/후)`).

→ **원문 질문을 FTS에 그대로 넣는 경로는 만들지 않는다.** FTS를 쓸 거면
  1단계에서 추출한 용어만 넣어야 하고, 그건 이미 intent 노드가 하는 일이다.

## 6. 0.45 기준선

**오탐 — 무관 질의 8건 중 2건이 기준선을 넘는다 (25%).**

```
파이썬 리스트 정렬하는 방법  → 신용등급 0.4888
비트코인 시세 알려줘        → 발행시장 0.4853
```

**누락 — 정답이 기준선에 걸려 잘린 것 1건.**

```
"보수" → 총보수요율 0.401  (기준선 0.45 미만)
```

**온톨로지 부재 질의(4건)는 오탐률에 넣지 않았다** — 관련 개념이 걸리는 것 자체는 정상이다.
다만 점수가 높다는 점은 위험하다.

```
만기수익률 YTM이 얼마인가요 → 연초이후 수익률 0.582   ← 온톨로지에 YTM 용어가 없다
샤프지수 알려줘            → 수치 스냅샷 0.5198
```

→ **0.45는 "관련 없음"을 판정하지 못한다.** 답변불가 판정을 이 점수에 맡기면 안 되고,
  TBox 검증(용어 존재 여부)이 별도로 해야 한다. 지금 설계(`src/tools/validate.py`)가 맞다.

## 7. 동의어가 가장 약하다 — 그리고 1차가 왜 이걸 못 봤는지

동의어 Top-1 엄격 **4/10**. 실패는 전부 "정답이 2위"다.

| 질의 | 1위 (오답) | 기대 |
|---|---|---|
| 채권 이자율 | 매수수익률 0.5841 | 표면금리 0.5542 (2위) |
| 보수율 | 매수수익률 0.5099 | 총보수요율 0.4973 (2위) |
| 펀드 규모 | 공모펀드 0.5889 | 순자산총액 0.5700 (4위) |
| 구성종목 | 기초지수 추종 0.4904 | 편입증권 **10위 밖** |

**`채권 이자율`은 1차 테스트에서 정답이었다.** 그때는 `매수수익률`이 코퍼스에 없었기 때문이다.
경쟁 용어가 들어오자 곧바로 뒤집혔다. 표본 크기 문제의 가장 직접적인 증거다.

`구성종목`은 상위 10위 안에도 없다 — 유일한 Recall@3 실패 2건 중 하나다.

## 8. 판정

```
인프라 · 검색엔진 전환      PASS         (1차에서 확정, 2차에서 유지)
실서비스 검색 품질          조건부 PASS   (Top-1 75% / Recall@3 96.7%)
```

**이전은 진행해도 된다.** 다만 아래 넷은 이전과 함께 반영해야 한다.

| # | 조치 | 근거 |
|---|---|---|
| 1 | grounding에 **Top-3 전달** (Top-1 아님) | 1·2위 점수차 30%가 0.02 미만 · R@3 96.7% |
| 2 | **RRF 기본 경로 제외** | 하이브리드가 벡터 단독보다 -1 |
| 3 | FTS는 **추출된 용어만** 투입 (원문 질문 금지) | 35문항 AND 0/35 · OR은 정밀도 붕괴 · 특수문자 구문오류 |
| 4 | 답변불가 판정을 **0.45에 맡기지 않는다** | 무관 질의 25%가 기준선 통과 |

`BOND_SCORE_FLOOR = 0.45` 자체는 유지한다. 낮추면 오탐이 늘고, 올리면 `보수`(0.401) 같은
정답이 더 잘린다. 이 값은 "노이즈 컷"이지 "관련성 판정"이 아니다.

## 9. 이번에도 검증하지 않은 것

- **답변 정확도가 아니라 검색 정확도만 쟀다.** LLM이 이 후보로 옳은 답을 쓰는지는 별개다.
- 질의 72건의 gold는 **내가 지정한 것**이다. 동의어는 원문 부재를 확인했지만(`쿠폰금리`·`이자율`·
  `보수율`·`펀드 규모`·`구성종목` 0건), 혼동군의 정답 선택에는 판단이 들어갔다.
- 코드리스트 개체 91건은 **인덱스에 없다**(`rdfs:comment` 부재로 수집에서 빠짐). 130건은 전체가 아니다.
