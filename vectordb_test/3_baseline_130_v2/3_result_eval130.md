# 130_v2 / 221 코드리스트 추가 영향 검증 보고서

## 1. 테스트 목적

`src/kb/build_bond_index.py`는 `rdfs:comment`가 있는 subject만 인덱스에 모은다.

 그 결과 온톨로지에
`rdfs:label`은 있으나 `comment`가 없는 **코드리스트 개체 91건**(신용등급 AAA/AA+, 투자지역,
자산군, 담보유형 …)이 검색 대상에서 통째로 빠져 있었다.

이번에 91개를 130개와 같이 넣은 건  **실험적으로 “**`comment`가 없는 **코드리스트 개체 91건 값들까지 TBox Vector Search에 넣으면 어떤 일이 생기나” 확인한 것**에 가깝다

결과는  `AAA`, `A`, `BB`, `장기`, `담보부` 같은 ABox/코드값 성격의 항목이 TBox 개념과 동일한 Top-K 슬롯에서 경쟁하면서 근거가 있는 schema term을 밀어냈다는 결과로

기존의 기획을 검증하는 방향으로 나왔다.Top-5 comment coverage가 100%→68.6%로 떨어진 게 그 증거야



&nbsp;

이 테스트의 목적은 하나다.

> **91건이 들어온 것 자체가 기존 검색 성능을 얼마나 흔드는가.**

사람이 `rdfs:comment`를 써 넣으면 "91건 추가 효과"가 아니라 "사람이 쓴 설명 효과"를 재게 되므로,
**TTL은 읽기만 하고 수정하지 않았다.** 수집 조건만 `comment 존재` → `comment 존재 OR label 존재`로
바꿨다.



측정은 두 단계로 나눴다.


| 단계               | 비교                  | 목적                |
| ---------------- | ------------------- | ----------------- |
| **130 → 130_v2** | 코퍼스 동일, 측정기만 결정성 확보 | **잡음 폭**을 먼저 확정한다 |
| **130_v2 → 221** | 코퍼스만 변경             | 잡음 폭을 뺀 **순수 효과** |


잡음 폭을 모르면 델타가 나와도 그게 신호인지 흔들림인지 판정할 수 없다. 그래서 130 재측정을
선행 필수 작업으로 두었다.

### 이 테스트가 답할 수 없는 것

동결 질의셋 72건에는 **코드리스트 개체를 정답으로 하는 질의가 0건**이다(`AAA 등급이 뭐야` 류).
이득을 잴 질의가 없으므로 이 프로토콜은 구조적으로 **손해만** 관측한다. 결론의 부호가 이미
정해져 있다는 뜻이다.

- **"얼마나 흔드는가"(회귀량)** → 유효
- **"넣을 것인가"(의사결정)** → 무효. 별도 질의셋 필요 (§10)

### 3.1 동결본을 값으로 읽어야 하는 이유

`eval130_queries.py`는 **import 시점에** `bond_terms.json`을 읽어 `_family("등급")` 같은 정답
집합을 계산한다. 재빌드 후 이 모듈을 호출하면 `등급` 어군이 14→28로 커져 **정답 집합 자체가
달라진다.** 그러면 전/후 비교가 성립하지 않는다.

→ 파이프라인은 `results/2_baseline_130.json`의 `resolved_queryset`을 **값으로** 읽는다.

세 baseline의 무결성 해시가 동일함을 매 실행마다 확인한다.

```
2_baseline_130      resolved_queryset_sha = 98b2c6d3019c1031
3_baseline_130_v2   resolved_queryset_sha = 98b2c6d3019c1031
3_baseline_221      resolved_queryset_sha = 98b2c6d3019c1031
```

`corpus_sha`는 `dd44518168541b10` → `33fb1da1cb9f6925`로 바뀐다. **재빌드했으므로 정상이다.**

## 4. 평가 지표

130 baseline의 6개 지표를 그대로 쓰고 **2개를 추가**했다.

### 4.1 ~ 4.6 (130 baseline과 동일)

Top-1 Strict / Top-1 Lenient / Recall@3 / FTS Hit / Hybrid Top-1 / Noise False Positive.
정의는 `results/2_baseline_130_report.md` 4절을 따른다.

### 4.7 근거 커버리지 (신규) — 이번 테스트의 핵심 지표

**Top-3 및 Top-5 결과 중 `comment != ""`인 건수.**

이 지표가 필요한 이유는 답변 단계의 계약에 있다.

```
src/agent/nodes.py:24   "아래 RETRIEVED SCHEMA의 comment 안에 적힌 문장만 근거로 삼는다.
                     comment에 없으면 없는 것이다."
src/agent/nodes.py:52   comment: {h['comment']}          ← 신규 91건은 빈 문자열
```

그리고 검색 도구가 슬롯을 먼저 자른다.

```
src/tools/bond_schema.py   index.search(q, min(k, index.ntotal))   # k = BOND_TOP_K = 5
                       → 5건을 먼저 자르고, floor 는 그 다음에 적용
```

즉 **신규 용어가 Top-5에 들면 comment 보유 용어를 밀어낸다.** term_uri 일치 Top-1이 올라가면서
답변 근거는 사라지는 구간이 실재한다. Top-1 정확도만 보면 이 피해가 보이지 않는다.

### 4.8 tie 잡음 폭 (신규)

`baseline_130` → `baseline_130_v2`의 델타. 코퍼스가 같으므로 이 차이는 **전부 측정기 잡음**이다.
221 델타를 읽을 때 "이 폭 안은 신호가 아니다"의 기준선이 된다.

## 6. 주요 발견

### 6.1 진짜 회귀는 0건이다 — 손실 전부가 신규 term 치환

Top-1이 바뀐 19건을 분류했다.

```
① 기존 → 기존 (진짜 회귀)     0건
② 기존 → 신규                19건
```

**기존 용어끼리의 역전은 하나도 없다.** 91건이 기존 용어 사이의 순위를 흐트러뜨린 게 아니라,
전부 자기가 1위 자리를 가져갔다.

#### 결론

"91건이 기존 검색을 망가뜨렸다"는 서술은 부정확하다. 정확히는 **91건이 상위 슬롯을 점유했다**이다.
이 구분이 중요한 이유는 대응이 다르기 때문이다 — 전자면 임베딩·점수 문제이고, 후자면
**슬롯 배분 문제**다. 후자의 처방은 인덱스 분리 또는 k 확대이지 재임베딩이 아니다.

### 6.2 ② 19건은 자동 판정하지 않는다 — 사람이 나눠야 한다

동결 정답에 91건이 없으므로 집계상 전부 오답으로 잡힌다. 그러나 **밀어낸 것이 옳았는지 틀렸는지는
집계가 답할 수 없다.** 답변 가능 카테고리 11건 전문:


| 질의                | 기존 1위          | 신규 1위                              | 마진          | 집계    |
| ----------------- | -------------- | ---------------------------------- | ----------- | ----- |
| 이 채권에 담보가 잡혀 있나요? | 담보 유형 0.5649   | 담보부 `fp:Collateral_Secured` 0.5725 | +0.0076     | 정답→오답 |
| 채권 이자율            | 매수수익률 0.5841   | 채권 `fp:AssetType_Bond` 0.5999      | +0.0158     | 오답→오답 |
| 쿠폰금리              | 표면금리 0.5929    | 변동금리 `fp:Coupon_Floating` 0.6085   | +0.0156     | 정답→오답 |
| 신용평가 등급           | 신용등급 0.6471    | 등급 보유 `fp:Rated` 0.6485            | **+0.0014** | 정답→오답 |
| 등급                | 신용등급 0.5731    | 등급 보유 `fp:Rated` 0.6706            | +0.0975     | 정답→오답 |

| 투자위험등급            | 투자위험등급 0.6217  | 보통 위험(4등급) `fp:RiskGrade_4` 0.6266 | **+0.0049** | 정답→오답 |
| 위험등급 수준           | 위험등급 수준 0.6572 | 보통 위험(4등급) `fp:RiskGrade_4` 0.6577 | **+0.0005** | 정답→오답 |


정답→오답 9건이 lenient −9와 정확히 일치한다.

판정을 나눠보면 성격이 갈린다.

- **valid replacement 후보**: `담보` → `담보부(fp:Collateral_Secured)`. 사용자가 "담보"를 물으면
담보 *유형이라는 개념*보다 담보부라는 *값*이 답에 가까울 수 있다.
- **invalid displacement**: `쿠폰금리` → `변동금리`. 쿠폰금리는 표면금리의 동의어이지 변동금리가
아니다. **명백한 오류다.**
- **판정 보류**: `만기` → `만기경과`. 마진 0.0003이라 어느 쪽도 근거가 없다.

#### 결론

**마진 0.005 미만이 4건**이다. 사실상 동점에서 신규가 이겼을 뿐이라 순위가 의미를 갖지 못한다.
이 4건은 "성능이 나빠졌다"가 아니라 **"순위가 판별력을 잃었다"** 로 읽어야 한다.

### 6.3 진짜 피해는 근거 손실이다

Top-5 근거 수가 줄어든 질의가 **47/72**다. 그중 치명적인 것은 근거가 **0**이 된 경우다.

```
답변 가능 60건 중 Top-5 근거 0건 :  2건  ("등급", "보수")
신규 용어의 Top-5 슬롯 점유 평균  :  1.2 / 5
5칸 전부를 신규가 점유한 질의     :  2건
```

`src/tools/bond_schema.py`가 k=5를 먼저 자르므로, 이 2건은 **근거 0건 상태로 답변 단계에 들어간다.**
`src/agent/nodes.py`의 계약("comment에 없으면 없는 것이다")을 그대로 따르면 모델은
"제공된 스키마에 정의돼 있지 않습니다"라고 답해야 한다.

`exact` 카테고리를 보면 문제가 더 분명하다.

```
Top-1 정확도  12/12  유지     ← 지표는 멀쩡해 보인다
근거 커버리지 60/60 → 48/60   ← 실제로는 20% 손실
```

#### 결론

**Top-1 정확도만 보면 이 피해가 보이지 않는다.** 검색 지표가 개선되면서 답변 품질이 떨어지는
구간이 실재하므로, 코드리스트를 다룰 때 term_uri 일치율은 단독 판단 근거가 될 수 없다.

### 6.4 Recall@3 96.7% → 90.0%, 빠진 4건은 전부 `등급` 계열

```
Recall@3 에서 빠진 질의: 등급 · 보수 · 채권 신용등급 · 평가사 등급이 몇 개인가요
```

4건 중 3건이 `등급` 어군이다. 130에서 이미 14개가 경쟁하던 구간에 19개(CreditRating) + 6개
(RatingBand) + 6개(RiskGrade)가 추가로 들어왔다.

#### 결론

130 baseline에서 확정한 "**Top-3를 전달한다**" 정책은 221에서도 유효하지만(90.0%),
`**등급` 계열에서는 Top-3로도 부족하다.** 이 어군만 별도 처리가 필요하다.

### 6.5 noise 오탐 25% → 50%는 성능 저하가 아니라 임계 재보정 신호다

130 baseline에서 부분표본으로 확인한 바, 코퍼스 크기 효과는 **N=65에서 이미 포화**한다
(N=20 17.7% → N=65 24.8% → N=130 25.0%). 따라서 130→221의 크기 증가만으로는 25%→26% 정도가
예측값이었다. 실측은 **50%**다.

범인은 명확하다.

```
파이썬 리스트 정렬     → A     0.5220      ← 한 글자 레이블
어제 축구 경기 결과    → A     0.4962
이 영화 재미있나요     → A     0.4324
서울 날씨 알려줘      → BB    0.4109
비트코인 시세 알려줘   → 통화   0.5139
병원 예약하고 싶어요    → 등급 보유 0.4580
```

**한두 글자짜리 등급 레이블(`A`, `BB`)이 무관 질의에서 0.45를 넘는다.** text 길이 중앙값이
기존 117.5자 vs 신규 27.0자다. 짧은 텍스트는 코사인 점수 분포 자체가 다른 레짐에 있다.

#### 결론

`BOND_SCORE_FLOOR = 0.45`는 **긴 comment 문서 레짐에서 실측해 잡은 값**이다. 그 절대 임계를
27자짜리 코드값 문서군에 그대로 적용하는 것은 범주 오류다. 91건을 넣으려면 floor를 문서군별로
나누거나, 애초에 인덱스를 분리해야 한다.

### 6.6 `absent` 카테고리는 전제가 이동했다

`신용등급 AAAA인 채권`은 "온톨로지에 해당 용어가 없다"는 전제로 분류했으나, 221에는 AAA 등급
개체가 실재한다(→ `fp:Rating_AAA` 0.5870). 라벨의 의미가 달라졌다.

#### 결론

이 4건은 221 해석에서 제외한다. 다음 질의셋 개정 시 재분류가 필요하다.

## 9. 이번 테스트가 검증하지 않은 것

### 9.1 91건의 이득

동결 질의셋에 코드리스트를 정답으로 하는 질의가 0건이라 **이득을 잰 적이 없다.** 판정 FAIL은
"손해가 확인됐다"이지 "이득이 없다"가 아니다.

### 9.2 LLM 답변 정확도

근거 커버리지는 **프록시**다. 실제로 답변이 나빠지는지는 3단계까지 돌려봐야 안다.

### 9.3 길이 레짐과 91건 효과의 분리

신규 91건은 (a) 코드리스트라는 점과 (b) 텍스트가 27자로 짧다는 점을 동시에 갖는다. 이번 측정은
둘의 **합**만 관측했다. 다만 짧음은 그 91건의 고유 속성이므로 회귀 측정 자체는 유효하다.

### 9.4 ② 19건의 valid / invalid 판정

§6.2에 목록을 전부 실었으나 **사람의 판정이 아직 없다.** 자동 판정하지 않았다.

## 부록 A. 재현

인자 형태는 이렇다. 기본값은 전부 130 계열이므로 **221은 인자를 반드시 넘겨야 한다.**

```bash
cd vectordb_test/3_baseline_130_v2

python3 ../../kb/build_bond_index.py                                     # API 91회, 약 122s

```

2)의 재빌드는 `artifacts/bond_terms.json`을 221건으로 덮어쓴다 — 130 스냅샷은
