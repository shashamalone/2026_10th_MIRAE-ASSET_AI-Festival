# eval221 — 코드리스트 91건 추가 전/후 (동결 질의셋 72건)

측정 대상: `rdfs:comment` 있는 130건만 넣던 검색 인덱스에 `rdfs:label`만 있는
코드리스트 개체 91건을 더해 **221건**으로 만들었을 때, 기존 검색이 얼마나 흔들리는가.

TTL은 건드리지 않았다. `rdfs:comment`를 새로 써 넣지 않았으므로 이 측정은
"91건이 들어온 효과"이지 "사람이 쓴 설명의 효과"가 아니다.

> **이 문서가 답하지 못하는 것**: "91건을 넣어야 하는가."
> 동결 질의셋 72건에는 코드리스트 개체가 정답인 질의가 **0건**이다. 이득을 잴 질의가
> 없으므로 손해만 관측된다. 결론의 부호는 측정 전부터 정해져 있었다. → Action 3 필요.

`terms130` 테이블 보존(130행), `results/bond_terms_130.snapshot.json`·`bond_130.faiss.snapshot` 보존.

재사용이 성립한 이유: 기존 130건은 전원 `alt_labels`가 비어 있어 조립 순서를
`uri|label|comment|alts` → `uri|label|alts|comment`로 바꿔도 결과 문자열이 **바이트 동일**하다
(재빌드 전 드라이런에서 130/130 확인). 캐시 키가 `sha1(model\0text)`이라 그대로 적중했다.

## 0. tie 잡음 폭 — `baseline_130` → `baseline_130_v2`

221과 비교하기 전에, 측정기 자체를 바꾼 몫을 먼저 분리했다.
변경은 두 가지뿐이다: keyword `ORDER BY r DESC` → `ORDER BY r DESC, term_uri`, 벡터 `k=10 → 30`.

| 지표 | 130 | 130_v2 | 델타 |
|---|---|---|---|
| strict Top-1 | 39/52 | 39/52 | 0 |
| lenient Top-1 | 51/60 | 51/60 | 0 |
| Recall@3 | 58/60 | 58/60 | 0 |
| noise FP | 2/8 | 2/8 | 0 |
| **RRF Top-1** | 50/60 | **49/60** | **-1** |

- 벡터 Top-1은 **72건 전부 동일**. 벡터는 tie-break와 무관하므로 예상대로다.
- keyword 결과 순서가 바뀐 질의 3건(`등급`·`수익률`·`발행`), 그중 2건이 하이브리드 1위를 바꿨다
  (`신용평가 등급` fp:CreditRating→fp:CorporateBond, `발행` fp:issuedAmount→fp:issuedByCompany).
- **→ tie 잡음 폭 = RRF Top-1 ±1. 벡터 계열 지표는 0.** 아래 221 델타에서 RRF의 -4 중
  최대 1은 잡음, 벡터 계열 -5/-9/-4는 잡음으로 설명되지 않는다.

## 4. ③ 근거 손실 (①②와 독립)

`src/agent/nodes.py:24`는 "comment 안에 적힌 문장만 근거로 삼는다"이고 `:52`가 comment를 렌더한다.
신규 91건은 comment가 **빈 문자열**이므로, 상위 슬롯을 차지하면 Top-1이 맞아도 인용할 문장이 없다.

- Top-5 근거 수가 줄어든 질의 **47/72건**. Top-3 100% → 76.4%, Top-5 100% → 68.6%.
- **답변 가능 60건 중 Top-5 근거가 0인 질의 2건**: `등급`, `보수`.
  이 두 건은 `src/tools/bond_schema.py`가 k=5를 먼저 자르고 floor를 나중에 적용하므로
  **근거 0건으로 답변 단계에 들어간다.**
- 신규 용어의 Top-5 슬롯 점유(답변 가능 60건): 평균 1.2/5, 3칸 이상 점유 12건, 5칸 전부 2건.
- exact 12건은 Top-1이 하나도 안 틀렸는데도 근거는 60/60 → 48/60으로 줄었다.
  **Top-1 정확도만 보면 안 보이는 손실이다.**

## 5. noise 오탐률 — 길이 레짐 판별

25% → **50%**. 부분표본 실측상 코퍼스 크기 효과는 N=65에서 이미 포화했고(N=20 17.7% →
N=65 24.8% → N=130 25.0%), 91건 추가로 두 배가 된 것은 크기 효과로 설명되지 않는다.

text 길이 중앙값 — 기존 **117.5자** vs 신규 **27.0자**(SQL 실측).
짧은 문자열은 코사인 점수가 전반적으로 높게 나온다. **0.45는 신규 문서군에 범주 오류다.**
→ 성능 저하로 읽지 말고 **임계 재보정 신호**로 읽어야 한다. 다만 재보정 자체는 이번 범위 밖이다.
